03 / What each adjustment does

The same camera, one setting changed

Choose a comparison. The left stays at the default; the right is a new render from the changed setting. These are generated cameras, so fitting participates in lens changes.

Generated camera

A narrower FOV triggers fitting, changing perspective and background coverage while retaining room for the actor. Distance scale controls how loose the fit is.

Manual exception

Changing Transform in Unreal pins placement. Shared fitting no longer moves it. Lens inheritance remains independent; explicit dolly/world-Z moves deliberately move and pin affected cameras.

Exposure is also a starting-point decision

04 / One camera, one blocker

Hide this column only for this view

The approved Review Set contains four Views. The first has one hidden actor; the other three have none. This is camera-local culling.

Protect means “keep it visible if a Hide rule includes it.” It can preserve an actor for one camera when a broader scope hides it. The subject is protected automatically. Supported exclusions remain loaded, opaque, non-Nanite static-mesh actors.

06 / Where sync stops

Unreal ↔ package works. Electroswag is not wired in.

↔
Optional C++ bridgeTransient cameras and native events
↔
unreal-rc → Node hostDurable draft and approval
No Electroswag synchronization is demonstrated here. Its checked consuming code has not adopted the new arrangement/panel session APIs. The existing cameras dependency and older capture tools do not automatically provide this authoring integration.

A studio can adopt the reference menu, replace it through public bridge/package contracts, or use the CLI. Electroswag still needs to host the arrangement session, display revision/pending state, and expose the saved View library. The broader sync-layer concept remains separate work.

07 / What the visual journey found

Working primitives; unfinished author experience

Enter can undo the entered value

Latest staged binary: FOV 45° → type 40° → Enter. The durable draft becomes 40°. Move focus: the draft returns to 45°. Committing with Tab worked in this journey.

This remains unfixed. The earlier backend/protocol tests did not exercise the actual keyboard/focus sequence.
