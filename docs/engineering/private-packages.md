# Private package ledger

The protected allowlist in `scripts/pack-public-packages.ts` is the only publishable npm surface.
Every other top-level workspace remains `private: true` for one of the reasons below. Revisit this
ledger whenever a package joins the synchronized public suite.

| Workspaces                                                                                                                                                                                                                                                                                                                                        | Why they remain private                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `apps/cli`, `apps/site`, `apps/workbench`                                                                                                                                                                                                                                                                                                         | Product distributions, not reusable library boundaries.                                                       |
| `examples/authoring-headless`                                                                                                                                                                                                                                                                                                                     | Example application whose dependencies, not the example itself, are the supported surface.                    |
| `packages/asset-audits`, `packages/enhanced-input`, `packages/scenarios`                                                                                                                                                                                                                                                                          | Domain implementations still awaiting a complete public API, packed-consumer journey, and support contract.   |
| `packages/authoring`, `packages/authoring-catalog`, `packages/authoring-sdk`                                                                                                                                                                                                                                                                      | Authoring internals are still being consolidated into a stable adoption boundary.                             |
| `packages/host`, `packages/ui`, `packages/ui-theme`                                                                                                                                                                                                                                                                                               | First-party extension host and presentation implementation; Workbench must not become a library prerequisite. |
| `extensions/asset-audits`, `extensions/asset-inspector`, `extensions/blueprint-graphs`, `extensions/camera-review`, `extensions/config-explorer`, `extensions/content-observatory`, `extensions/data-authoring`, `extensions/game-text`, `extensions/input-atlas`, `extensions/project-custodian`, `extensions/scenarios`, `extensions/sequencer` | Workbench extension entry points and UI composition, not headless package boundaries.                         |

Promotion requires public metadata and licensing, a browser-safe entry point where relevant, exact
internal dependency pins, a clean offline packed-consumer journey, and an explicit Changesets entry.

[`@ue-shed/localization`](../../packages/localization/README.md) is in the public suite. It owns
read-only localization formats and evidence independently of the Game Text corpus and Workbench.
Its Node entry also depends on public `@ue-shed/engine` for the separately enabled localization
process capability; browser consumers receive pure planning and no engine/process authority.
