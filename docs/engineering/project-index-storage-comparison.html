What SQLite proved

Batching rescued the row store.

Four header workers, a bounded 1,024-result window, and 1,024-entry SQLite batches cut cold mean from 35.39 seconds to 25.72 seconds. Small mutations remained exceptional: 19.3 ms for one changed package and 18.7 ms for one deletion.

What DuckDB proved

OLAP wins only when the Adapter speaks OLAP.

Removing indexes and N+1 hydration turned the same engine from a 68.64-second failure into a 21.63-second result. The public Catalog Interface did not change. Implementation Depth did the work.

07 / METHOD

What these numbers do—and do not—prove.

The report separates measured facts from architectural inference. Every production selection still depends on conformance, recovery, packaging, and license gates.

Equal-workload lane

SQLite and both DuckDB adapters used the same coordinator, 185,676-package project, 17 bounded pages, three cold samples, three timed warm samples, and one warmup.

Legacy lane

The clean-worktree pre-SQLite result used the same project and machine class but a different contract: complete inventory transfer, 734 emitted headers, and targeted Input decode. It is intentionally labeled non-equivalent.

Model-research lane

Nested lists, row groups, ordering, threads, checkpoints, and immutable copying were tested against representative Catalog evidence. They are subsystem measurements, not projected cold starts.

Cold means cache-cold

The Catalog or legacy header cache was removed before each cold sample. Filesystem caches were not forcibly purged, so this is not a cold-disk benchmark.

Privacy

Retained result JSON contains aggregate durations, counts, sizes, and resource peaks. It contains no project paths, package paths, asset identities, class values, or serialized-name values.

Still gated
  • 11 shared Catalog scenarios passed for the columnar probe.
  • Direct Rust Arrow/List ingestion is not yet measured.
  • DuckDB adds ~25.9 MB to the EXE and ~140 locked packages.
  • License and offline release gates remain.
