# UE Shed 0.10.0

UE Shed 0.10.0 adds a localization workspace to Game Text, reads saved Game Text from Unreal 4.27
through 5.3, and gives headless hosts initialized authoring defaults, text identity and optional
runtime automation. It is the first release of `@ue-shed/localization`. All 20 public npm packages
and eleven Unreal plugins advance to 0.10.0 together; packages without direct changes advance for
suite alignment and exact dependencies.

## Localization workspace

- New public `@ue-shed/localization` package. It discovers localization targets from Dashboard
  settings or recipe configs, and reads manifests, archives, locmeta and word-count reports in the
  Unreal 4.27, 5.7 and 5.8 layouts. Its PO model round-trips byte for byte.
- `@ue-shed/game-text` joins saved text with that evidence by namespace and key. Each line and
  culture gets one state, such as translated, not translated, needs update or not synced; coverage
  gaps read as `unknown` with a reason. String Table translator comments now reach translator notes.
- Eight built-in checks cover format arguments, plural and gender modifiers, rich-text tags, unsafe
  PO escapes, whitespace, empty entries, missing translator notes and duplicate sources. They check
  the translation that the next sync will ship. Suggested fixes are version 1 change-set proposals.
- Rule documents version 2 add per-culture budgets and glossaries; version 1 is unchanged. Reports
  give per-culture progress with Unreal's own word counts and compare against saved baselines.
- Gather, import, export, compile, reports and sync run as owned Unreal processes with progress,
  cancellation, typed failures and receipts. Every plan lists the files Unreal may write, so hosts
  can check them out first. UE Shed never passes source-control switches.
- Reviewed translation edits are written into PO files through an atomic, hash-guarded replace,
  after revalidation against the manifest source and the translation that ships next.
- Review state (reviewed, proofread, approved, machine translated, accepted findings) lives in one
  project-owned `Config/UEShed/Localization/<Target>.review.json` per target. An edit after review
  reads as changed since review.
- The CLI adds `ue-shed loc targets|status|check|report|run|apply|review`, plus
  `ue-shed text search --target/--culture/--state` and `ue-shed text rules init`.

UE Shed never writes manifests, archives, `.locres` or `.locmeta` directly. See
[ADR 0009](../decisions/0009-localization-change-sets-and-review-state.md) and
[Game Text](../products/game-text.md).

## Game Text for Unreal 4.27 through 5.3

- The native reader and WASM inspection read the legacy property tags used before UE 5.4, so
  String Tables, DataTable rows, data assets and generic UObject text extract from uncooked editor
  packages saved by UE 4.27 and 5.0–5.3.
- Each legacy record is bounded by its tag size. A value that cannot be decoded becomes a coverage
  gap with a specific reason and never shifts the stream.
- Text coverage gaps add `legacy_container_element_without_type_information`,
  `feature_unavailable_for_engine_version` and `property_decoder_rejected`.
- Blueprint pins, Sequencer, animation, property bags, InstancedStruct and actor/component native
  records keep their 5.7 and 5.8 gates. Packages saved before 4.27 still parse at header depth only.

## Headless authoring and automation

- Live snapshots publish initialized native and Blueprint DataTable defaults, and Authoring adds
  bounded, explicitly targeted actor and component row-reference lookup.
- Text values carry their localization identity (snapshot 2.3, Apply 1.2): localized namespace and
  key, String Table entry, culture-invariant, none, or read-only generated. Apply writes text from
  that identity and can mint a key in the table package. Apply 1.2 refuses to remove a row whose
  text identity changed since review.
- New optional runtime `UEShedAutomation` plugin: explicit local-player discovery, typed one-shot
  Enhanced Input, and plugin-owned CSV profiling captures. `@ue-shed/unreal-connection` exports
  typed headless clients that negotiate each optional capability.
- Producer refusals such as `invalid_request` and `operation_not_found` are typed
  `UnrealConnectionError` codes.
- A new `editor-host` plugin bundle preset combines camera authoring with DataTable authoring.

## Upgrade notes

Use matching 0.10.0 packages for suite alignment. Hosts that switch exhaustively on text coverage
gap reasons or `UnrealConnectionError` codes should handle the new values.

Apply 1.0 and 1.1 clients keep working. They compare display strings, rewriting an unchanged display
string keeps the existing identity, and the `sha256-v1` fingerprint excludes text identity. Use
Apply 1.2 to edit text identity. Hosts that want authoring defaults, row-reference lookup, text
identity or automation need the 0.10.0 Unreal plugins; automation additionally needs
`UEShedAutomation` enabled. CSV capture ownership is process-wide for the plugin, so hosts
coordinate access.

Native plugin compatibility targets Unreal 5.7 and 5.8. Compiled variants require matching engine
version, BuildId, platform and architecture.
