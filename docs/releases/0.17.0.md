# UE Shed 0.17.0

UE Shed 0.17.0 moves Game Text indexing and queries into the Rust engine, adds a separately enabled
`UEShedGameText` editor plugin that fixes text keys through Unreal, ships the Game Text workspace as
a library, and gives every tagged error the same recovery guidance. All 20 public npm packages and
twelve Unreal plugins advance to 0.17.0 together; packages without direct changes advance for suite
alignment and exact dependencies.

This release has breaking changes. Each section below names its migration.

## Game Text: native engine

- Indexing and query execution run in the Rust engine. Queries, counts, facets, groups, focus and
  exports use scoped native readers. Authored-source, String Table and localization-file updates
  publish incremental snapshots while existing readers stay pinned.
- Changed package records publish without decoding unchanged shard records in JavaScript.
  Dependencies for occurrences, source values and String Tables are indexed separately, so stable
  text edits locate affected groups through native reverse indexes.
- Uncached searches run over unique folded sources and localization counts. Search aggregates are
  reused within each immutable reader.
- **Breaking:** query methods return Effects. The in-memory query factories, the TypeScript index
  builder, the synchronous indexed projections and the search worker are removed. The native
  executable must support uasset-io protocol 1.16 and `game_text_engine_v1`. An unavailable or
  incompatible native reader is a typed failure; there is no JavaScript fallback.
- Use `GameTextIndexBuilderLive` with the host's `AssetReader`. The CLI, Workbench and packed-consumer
  conformance use the same native implementation.

## Game Text: fixing text keys through Unreal

- The new `UEShedGameText` editor plugin (ADR 0011) changes, regenerates and adopts text keys and
  retypes source in DataAsset properties, Blueprint class defaults, SCS component templates, widget
  trees, nested DataTable cells, graph text pins and String Table entries. It compiles each owning
  Blueprint, reads every place back and saves only when asked.
- `@ue-shed/protocol` adds the `ue-shed-game-text-actions` 1.0 contract. `@ue-shed/game-text` adds
  `runGameTextActions`, `gameTextActionsRequest`, `gameTextActionForOccurrence` and
  `verifyGameTextActions`.
- ID repairs are durable, host-neutral proposals with verified receipts. The Showcase can split
  conflicting sources, choose shared text and merge duplicate keys with an explicit preview,
  approval and recovery. A started repair is never replayed, including after a restart or a lost
  reply.
- String Table key migration copies the entry, retargets references, persists a redirect and can
  optionally delete the old entry, with saved-file verification. Migration keeps the old entry by
  default. A destination that already redirects to another key is refused before anything is
  written.

## Game Text: library and API

- `@ue-shed/game-text/workspace` exports `makeGameTextWorkspace(host)`, the scanning, search,
  quality, localization, review, report and investigation orchestration that the Workbench used to
  keep to itself. `makeGameTextOperations(host)` runs Unreal's localization steps.
- **Breaking:** focused entry points (`/schema`, `/rules`, `/checks`, `/labels`, `/corpus`, `/index`)
  export named items only. The root and `/browser` aggregates are deprecated, and storage internals
  are private. `WorkbenchOperation*` is renamed `GameTextOperation*`, with deprecated aliases.
- **Breaking:** result decoders are unary `parse*` parsers that fail with `GameTextResponseError`.
  Scan limits are the branded `TextCorpusScanLimit`.
- **Breaking:** progress is reported only through `GameTextIndexProgressReporter`.
  `localizationQuality(ruleDocument?, options?)` and `sourceQuality(ruleDocument)` take the rule
  document first and are required on refresh results.
- Scans read an external actor package only when its saved header says it holds gatherable text. On
  a large World Partition project this cut a scan from 429,625 packages (16.4 GB) to 9,056 (4.7 GB).
- `diffPackageText(before, after)` compares two copies of one package place by place.
- The reader decodes compiled Blueprint text literals (`ScriptBytecode[N]`, UE 4.27 to 5.8) and graph
  pins whose default text is a String Table reference.

## Localization checks

- Rule file version 3 sets each built-in check's `enabled`, `severity`, `scope` and `params` under
  `checks`. `migrateGameTextRuleDocument` rewrites v1 and v2 files as v3 with the same behaviour.
- Scope (cultures, roles, object path prefixes) now limits where findings are reported.
- Rule files can define up to 512 `customChecks` (`pattern`, `length`, `forbidden_term`), reported
  as `LocalizationCustomFinding` (`kind: "custom"`).
- `localizationCheckCatalogue` describes every built-in check. Each finding's severity is stored, so
  per-check severities show in workspace pages exactly as in reports.
- **Breaking:** `checkSeverity` and `workspaceQualityLabels` are removed;
  `WorkspaceQualityFilter` is a union; `LocalizationFindingList` requires `severity(position)`. With
  `format_argument_renamed` or `rich_text_tags` disabled, their companion checks now report what
  those checks used to absorb.

## Errors and recovery guidance

- **Breaking:** every production tagged error carries `message`, `recovery`, `retrySafe` and a typed
  `nextStep` (`fix_input`, `retry`, `reconcile` or `escalate`). `retry` appears only when the error
  is retry-safe. A mutation whose outcome is unknown reports `reconcile`.
- Messages no longer embed a stringified cause; the original failure is kept on `cause`.
- **Breaking:** errors are matched by tag, not `instanceof`. Raw decoders in `map-history`,
  `observatory` and `project-custodian` become `parse*` with their own contract errors. Obsolete
  `*Shape` aliases are removed; use the `*Api` names.
- **Breaking:** test layers are complete fakes, and layers compose through requirements.
- Unreal plugins name their failures: Authoring Apply 1.3 adds a `cause` to each command error,
  Authoring Save 1.2 adds a `code`, camera bridge and camera control failures carry stable codes and
  valid JSON, and Observatory stream failures carry `code` and `retrySafe`.
- Native decode errors carry `field` and `offset` (uasset-io protocol 1.14), and the Rust crates no
  longer panic on malformed packages.

## Validation

Release preparation on 2026-10-19 uses Node 26.12.0 and pnpm 11.17.0 on release commit `23196329`.

- `pnpm check` passed (3,010 tests). `native-package-delta.integration.test.ts` previously timed
  out at 120 s under full-suite load with debug native builds; its budget is now 300 s.
- Clean pack (`pnpm release:pack:clean-check`): all public packages packed from a clean checkout of
  the release commit.
- Plugin compatibility gate (`pnpm test:unreal-plugins`): all 12 plugins built and 40 automation
  tests passed on both UE 5.7 and UE 5.8.
- Engine matrix (`pnpm test:uasset-engine-matrix`): UE 5.7 passed on one run and UE 5.8 on another;
  both runs were interrupted or hit environmental failures (a host restart, a concurrently rewritten
  editor settings file). The UE 4.27 legacy lane passed. The optional UE 5.3 legacy lane failed to
  build because UE 5.3 headers do not compile with MSVC 14.44. A full rerun and `pnpm check:unreal`
  on UE 5.7 were still running when the packages were staged; any issue they find ships in 0.17.1.
