# UE Shed 0.18.0

UE Shed 0.18.0 brings Game Text key repairs to Unreal 4.27 and extends the full plugin suite to
Unreal 5.6. The saved-asset reader also learns to read Blueprint graph pins. All 20 public npm
packages and twelve Unreal plugins advance to 0.18.0 together; packages without direct changes
advance for suite alignment and exact dependencies.

This release has no breaking changes.

## Engines: Unreal 4.27 and 5.6

- **New 4.27 `game-text` preset (4.27–4.27.2):**
  - It builds a minimal UE4Editor bundle: `UEShedGameText` plus a runtime-only `UEShedCore`.
  - It advertises `game-text.actions.v1` and the narrow `game-text.actions.key-repairs.v1`.
- **Plugin distribution and UE4:**
  - `@ue-shed/plugin-distribution` supports exact UE4Editor compiled variants and UE4 AutomationTool
    discovery.
  - It accepts the minimal Game Text release asset names.
- **Full UE5 suite:** the suite and its existing presets now cover Unreal 5.6 through 5.8.2,
  including cameras.
- **UE4 limits:** 4.27 still can't edit DataTable cell or graph pin source text, and can't migrate
  String Table keys.

## Game Text: key repairs without full editor tooling

- **Capability:** the key-repair capability is admitted independently of full localization authoring.
- **Simple DataTable ID repairs:** these run through native Game Text when Authoring is absent.
- **Cell-key regeneration:** this always uses native Game Text, even when Authoring is present,
  because Authoring's cell commands cannot generate new keys.
- **String Table migration:** project checks use Core's `projectRoot` fact, or an explicit host
  callback, without editor-world control.
- **Unchanged:** receipts, expected-value checks, session binding and saved-file verification.

## Saved-asset reader: Blueprint graph pins

- **Pin text:** saved graph pin text is read on UE 4.27 and UE 5.6–5.8, keeping Unreal identities and
  addressable pin locations.
- **Compiled literals:** these join the matching saved pin's identity within the package, so one
  piece of Blueprint text is one unit with both occurrences. Different sources, other packages and
  unread pins stay separate.
- **Honest coverage:** skipped, rejected or unread graph pin streams, including a custom graph whose
  node list can't be read, report partial coverage with a named `Pins` gap. That holds even when the
  package's gather table omits their text.
- **Repair verification:** saved repair verification matches native subobject paths.
- **Cached scans:** cached package text is re-extracted on the next refresh, so existing scans gain
  pin text.

## Unreal Editor: opening assets

- `UEShedCoreEditor` negotiates a separate `editor.asset-open.v1` capability.
- `@ue-shed/unreal-connection` adds `openUnrealAsset({ endpoint, objectPath, bringToFront })`.
- The `unreal-editor-asset-open` 1.0 contract reports:
  - accepted opens as `ok`;
  - missing assets, load failures and editor refusals as `unavailable`, with recovery guidance.
- Locate still only reveals assets in the Content Browser.

## Failures that read honestly

- **Plugin store:**
  - A lease that can't be read, or is still being written, keeps its release from being pruned.
  - Only a lease that stays undecodable for 30 seconds counts as abandoned.
  - A cache lock that can't be read is treated as held.
- **Release integrity check:** an archive that can't be hashed fails the check.
- **Review authoring sessions:** a Review Set is reported missing only when its file is gone. One
  that can't be read or doesn't decode fails with its own reason, so a recoverable session isn't
  discarded.
- **Native camera render policies:** these reject non-boolean values instead of coercing strings and
  numbers.
- **Error standard:** `docs/engineering/types-and-errors.md` adds message-writing and
  translation rules. The new `anti-slop/no-effect-catch-all` lint rule flags Effect catch-alls, with
  existing ones baselined.
