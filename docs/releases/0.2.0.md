# UE Shed 0.2.0

UE Shed 0.2.0 turns three Workbench-proven capabilities into supported headless libraries and ships
the Map Capture and editor-world work accumulated since 0.1.0. All 14 public npm packages use the
same 0.2.0 version; packages without a direct behavioral change are republished for suite alignment.

## Highlights

- New `@ue-shed/engine`: discover Epic and registered source builds, resolve a project's engine
  association, launch projects with optional plugins and Remote Control, wait for the matching
  editor, control PIE, and load or inspect the editor world.
- New `@ue-shed/config-explorer`: explain the ordered Unreal `.ini` hierarchy, effective values,
  source contributions, platform comparisons, missing layers, and unsupported syntax without
  launching the editor.
- New `@ue-shed/project-custodian`: scan regeneratable project and engine storage, create durable
  reviewed proposals, default execution to Trash/Recycle Bin, and refuse stale plans, unsafe paths,
  or cleanup while Unreal Editor is running.
- Map Capture now has portable saved plans, safe editor map control, editor-world previews that do
  not require PIE, orthographic tile-pyramid capture, per-zoom LOD policy, independent fog controls,
  neutral hashed manifests, resumable/pipelined capture, and a viewport high-resolution backend.
- Map Review retains every non-discarded framing candidate when adding a subject and uses realized
  projection evidence for trustworthy editor-world previews, including orthographic previews.
- Protocol and connection boundaries now preserve JSON-safe Remote Control values and stricter
  identifier decoding, and camera provisioning correlates results with the expected map.

## Compatibility notes

- `ProvisionedCameraSpec.projection` is now a discriminated perspective/orthographic object rather
  than the earlier flat projection fields.
- `ensureProvisionedCameras` requests must include `expectedMapPath`.
- The camera provisioning request contract is version 3. Decoders retain compatibility with v1 and
  v2 inputs where documented, but new producers emit v3.
- Protocol identifier decoders accept strings at their external boundary and reject invalid values
  instead of accepting already-branded inputs implicitly.
- `RemoteControlRequest.parameters` is a JSON object; non-JSON values are no longer part of the
  transport contract.

## Release evidence

The versioned 0.2.0 tree passes the complete portable package, packed-consumer, adoption, type,
lint, contract, Rust, WebAssembly, and test gate. The trusted Windows release machine also passes
the complete Unreal 5.7 gate: commandlet UAsset conformance, transactional authoring against real
assets, native camera and map-review integration, and the five live Workbench Map Review flows.
