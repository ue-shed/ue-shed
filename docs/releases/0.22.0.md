# UE Shed 0.22.0

UE Shed 0.22.0 moves Game Text's checks, findings and searches into one native engine session,
makes the project's rules file the only source of what is checked, and adds Input Atlas conflict
analysis. All 21 public npm packages and twelve Unreal plugins advance together, including the new
`@ue-shed/game-text-corpus`; packages without direct changes advance for suite alignment and exact
dependencies.

## Game Text engine

- The engine runs as its own binary session, `uasset game-text-engine`, in one process per host.
  Requests run concurrently, so a search answers while an evaluation or export runs. Cancelling a
  read cancels it in the engine, and a panic fails only its request.
- Bulk reads stream as column batches instead of temporary files, and exports are encoded by the
  engine into a file or a stream. The Workbench's 64 MiB cap on the all-languages CSV is gone, and
  `ue-shed loc check` prints its report as the findings are written, with unchanged bytes.
- Searches are `query` requests over cached row sets. The 50-row page cap is gone; a page can hold
  up to 100,000 rows, and a page over 500 rows streams.
- After an edit, a rescan re-evaluates only the changed lines and the rows that share a group or
  corpus count with them.

## Rules and findings

- The rules file restarts at `schemaVersion: 1`; versions 1–3 no longer load. A file is one
  `rules` list. Only what it lists runs, and without a file nothing runs. `STARTER_CHECK_RULES`
  gives today's default checks.
- `duplicate_source`, `inconsistent_translation` and `culture_invariant_text` run as native rules
  with the same findings. Browse's `shared` and `long` signals are opt-in checks.
- Complete rules (`kind: "rule"`) are written in the engine's rule language. A broken rule is
  reported as `invalid_expression` or `rule_cycle` with its `ruleId`. Rules take an optional
  `label` that their findings show.
- Browse's findings are the project's rules: searches, focus and line detail carry a `findings`
  layer. The search `lens` and the `shared`, `duplicate_source` and `long` signals are removed.
- Quality, source quality and `loc check` read findings from the engine; the Quality worker is
  gone. `ue-shed loc check --rules <file>` checks with another file.

## Hosts

- A workspace host can supply its starter rules file, a `prepareWrites` hook that checks out every
  PO or review file before the first write, and its name for recovery text. Polling an operation
  no longer starts a localization discovery, and scan progress reports `step` of `steps`.
- `applyLocalizationChangeSet` takes the same `prepareWrites` hook, called with the files it read
  fresh.
- `workspace.related` reads a unit's or line's related members in one request, and `searchRows`
  reads further pages and open groups without recounting.
- **New:** `@ue-shed/game-text-corpus` checks a host's index against a generated corpus's planted
  answers, so a host can verify its own composition.

## Input Atlas and CLI

Enhanced Input scan schema 2 adds the saved properties of actions, mappings, contexts, triggers and
modifiers, and projects Player Mappable Input Config assets. Co-activation sets classify contested
keys as shadowed, may shadow, both fire, ambiguous priority, qualified or cross-context, following
Unreal's consumption and chord rules. New `ue-shed input atlas`, `conflicts`, `unused`, `platforms`
and `export` commands accompany the route's conflict filter and platform view.

## Compatibility

Use matching 0.22.0 packages and plugin sources. uasset-io 1.20 adds package-text snapshots, and
the Game Text engine moves from the uasset-io `game_text_engine` operation to its own session.
Package text shards advance to `package-text-v10` and re-extract once. Rules files from 0.21.0 and
earlier must be rewritten in the version 1 format. Public package Node requirements remain as
declared in each package; repository release tooling uses Node 26.
