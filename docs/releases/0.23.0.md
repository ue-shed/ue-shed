# UE Shed 0.23.0

UE Shed 0.23.0 prepares the libraries for adoption by other hosts. Game Text keeps only its focused
entry points and gains a transport-neutral workspace contract. Editor launches take per-run
options, the asset reader batches large path lists itself, and errors carry shared recovery
guidance. All 21 public npm packages and twelve Unreal plugins advance together; packages without
direct changes advance for suite alignment and exact dependencies.

This is a 0.x minor with deliberate breaking changes. Read the next section before upgrading a host.

## Breaking changes and migration

### `@ue-shed/game-text`

[`ADOPTING.md`](../../packages/game-text/ADOPTING.md#migrating-to-023) has the full migration
table.

- **Root and `/browser` entry points removed**, with the package's `main` and `types` fallbacks.
  Import from the focused entry point that owns each name. In the browser, use `/schema`
  (contracts), `/rules` (rule documents), `/checks` (checks and filter helpers) and `/labels`
  (presentation). In Node, use `/corpus` (queries and reports), `/index` (scanning and native index
  composition) and `/workspace` (selected-project workflows and operations).
- **`WorkbenchOperation*` types removed** (`Request`, `Failure`, `Plan`, `PlanResult`, `Receipt`,
  `Result`, `Progress`, `State`, `Id`, `Target`, `FilesRequest`, `FilesResult`). Use the
  corresponding `GameTextOperation*` names from `/schema`.
- **`ScanTextCorpusOptions`** → `TextCorpusScanOptions` from `/index`.
- **`TextCorpusServiceShape`, `TextCorpusServiceTestShape`** → `TextCorpusServiceApi`,
  `TextCorpusServiceTestApi` from `/index`.
- **`TextReviewLens`** → `TextFilter` clauses from `/schema`: `finding` names rule IDs and `fact`
  names review signals. Saved investigation presets that still carry a `lens` open with the same
  selection, because `investigationRequest` reads the lens as its clause.
- **`TextFinding`, `TextCountedFindings`, `textFindings`, `textCountedFindings` and row
  `countedFindings`** → the row's `findings` rule IDs (`TextRowFindings` from `/checks`).
- **`GameTextIndexStepsOptions.qualityWorker`**: omit it. Quality runs in the native engine.
- **`gameTextCsv`** → `NativeTextQuery.writeCorpusCsv` on the opened index query.
- **`localizationLinesCsv`** → `NativeTextQuery.writeLocalizationLinesCsv` on the opened index
  query.
- **`prepareLocalizationFile`** → native index imports through `GameTextIndexSteps.importTarget`
  from `/index`.
- **Workspace methods take one argument object.** `configuredRefresh(refresh?)` →
  `configuredRefresh({ refresh? })`, `createStarterRules(loadExisting)` →
  `createStarterRules({ loadExisting })`, and `investigationExport(query, format)` →
  `investigationExport({ query, format })`.
- **Workspace progress carries phase codes, not English text.** `GameTextWorkspaceProgress` is now
  an Effect Schema from `/schema`. Its `stage` and `detail` are gone; read `phase` (a
  `GameTextWorkspacePhase`) and word it with `GAME_TEXT_WORKSPACE_PHASE_LABELS`, or an index phase
  with `GAME_TEXT_INDEX_PHASE_LABELS`, both from `/labels`. They keep the wording `detail` had.
- **The host's `project.progress()` returns `GameTextWorkspaceProjectProgress`** (`phase`,
  `completed`, `total`). Other fields a host's progress carries are ignored rather than passed
  through, so move anything a host relied on into its own channel.

### `@ue-shed/unreal-assets`

- **An oversized reader request fails with `request_too_large`**, a new `AssetReaderError` kind
  with `nextStep: "fix_input"`. It replaces the `contract` error, and its message no longer names
  `batchProtocolPaths`. Handle `request_too_large` where a host matched the old `contract` error.
  Path lists are now batched, so it only comes from a single path or option too large on its own,
  or a staging group that cannot fit one request.
- **The default reader is the packaged `uasset.exe`.** With no executable configured,
  `assetReaderLayer` and `AssetReaderLive` run the `uasset.exe` from the installed
  `@ue-shed/uasset-win32-x64` package before trying `uasset` on PATH, and `getAssetReaderSource()`
  can return the new value `"package"`. To keep a PATH or custom reader, configure it explicitly;
  `UE_SHED_UASSET_EXECUTABLE` still takes precedence for `AssetReaderLive`.

### `@ue-shed/engine`

- **Live Coding is turned off by an ini override.** Plugin sessions now pass
  `-ini:EditorPerProjectUserSettings:[/Script/LiveCoding.LiveCodingSettings]:bEnabled=False`
  instead of `-NoLiveCoding`, which is a build-tool switch the editor ignores. A host that matched
  or appended `-NoLiveCoding` itself should drop it.
- **Commandlets use `-SCCProvider=None` instead of `-nop4`**, which only AutomationTool reads.
  Niagara preview and other commandlets now really start without a source control provider.
- **Supervised sessions check the build before starting the editor.** A project compiled for
  another engine fails at once with `build_mismatch` (stage `validation`, next step `fix_input`)
  instead of a readiness timeout. `SupervisedEditorSessionError` gains the codes `build_mismatch`,
  `invalid_module_manifest`, `plugin_unavailable` and `engine_plugins_stale`, with the launcher's
  error as the cause; handle them wherever a host switches exhaustively on the code.
- **Launch errors gain `startup_map_missing`** for a `startupMap` that does not exist, raised before
  spawning.

### Errors and recovery guidance

- **World preparation errors accept only the documented client and editor failure codes**
  (`@ue-shed/world`). Each code carries its own recovery guidance, and an unknown producer code
  now fails contract decoding instead of passing through. Producers must send a documented code.
- **Niagara preview failures require `nextStep`** (`@ue-shed/niagara`). A host that builds or
  adapts these failures must supply the next recovery action.

### `@ue-shed/localization`

- **Write-audit limits now bound only hashed bytes.** The audit records every file's size and
  modification time and hashes only the plan's files and files that changed, so
  `LocalizationAuditLimits.maxFileBytes` and `maxTotalBytes` no longer count every project file.
  The default `maxEntries` is now 1,000,000. A change found by size or modification time alone
  carries `beforeUnread: true`, because the file's earlier content was not hashed; treat its
  `before` side as unknown.

## Game Text

- **New:** `GameTextWorkspaceContract`, from `/schema`, is the browser-safe contract of the Game
  Text workspace. For each `GameTextWorkspaceApi` method a host serves, it gives the params and
  success schemas, and for `progressChanges` each event's schema. It names no channels, so a host
  maps each method to its own IPC, WebSocket or MCP transport. Host-only methods (operation
  admission, `localizationBeforeGather` and `configuredScan`) are left out and listed in its doc
  comment.
- `GameTextIndexPhase` names the index's phase codes, and progress during a quality scan carries
  the findings so far.
- Quality evaluations on an opened index report progress again ("Checking source text", "Checking
  localization quality"), counting rules as they run, and return to idle when they end.
- A Scan that finds the project's text unchanged keeps the open index and its quality results, and
  a rules document equal to the published one reuses the quality already computed for it.

## Editor launches

`UnrealProjectLauncher` and supervised sessions take per-run options:

- `startupMap` opens a map directly (`/Game/Maps/Arena`) instead of loading the default map
  first.
- `logPath` writes the run's editor log to an absolute path, which the launch result, session
  handle and early-exit error name.
- `sourceControl: "disabled"` starts the editor without connecting to source control.
- `additionalArguments` passes other editor switches. Switches the launcher owns or that would
  break the session or project are refused with `invalid_request`; `reservedUnrealEditorArgument`
  gives the reason.
- With plugins, `remoteControlAllowedFunctions` allows single engine or project functions on UE
  5.8, and `remoteControlWebSocketPort` sets the WebSocket port.
- Supervised sessions add `unattended` (no dialogs; refused with `recovery_pending` while the
  project has unsaved work to recover) and `window: "offscreen"` (UE 5 only).
- `ProcessSupervisorExecutable` and `processSupervisorExecutableLayer(path)` let a host run the
  Windows process supervisor from its own location, such as an Electron app's resources.

## Asset reader

The reader splits a package path list too large for one 4 MiB request into consecutive batches,
one reader process at a time, so projects with tens of thousands of candidate paths no longer
fail. Scans return one merged result and projections stream the batches in order with one merged
summary. Repeated paths and paths beneath another requested directory are dropped, and each
package appears once. `maximumAssets` bounds the whole operation, a batched header scan keeps one
cache per batch, and cancelling stops the running batch. Projection streams now record their
protocol telemetry after the worker finishes instead of at creation, and each operation's span
records `ue_shed.reader.batches`.

## Localization, Niagara and protocol

- The localization write audit no longer reads the whole project. On a 35,000-file, 15.7 GB project
  it used to fail with `limit_exceeded` after 10 seconds; its first snapshot now takes 2.6 seconds.
- The UEShedNiagara preview commandlet ends a render frame after every scene capture and session
  request, so host-owned sessions no longer grow by about 400 MiB per request. When auto-fit
  coverage already reaches the image edge, the capture keeps the bounds-based camera and logs a
  warning instead of failing; edge activity still sets `needsReview`.
- **New:** `@ue-shed/protocol/errors` is a lightweight subpath with the same error schemas as the
  root export. Libraries and hosts share its guidance schemas, and Niagara session recovery, retry
  safety and next steps survive preview error adaptation.
- The CLI classifies plugin installation failures as input fixes, safe transient retries or
  escalation, and keeps command hints in its localization output while the libraries stay
  host-neutral. Enhanced Input reports malformed scan options as `invalid_options`.

## Compatibility

Use matching 0.23.0 packages and plugin sources. The Niagara change rebuilds the UEShedNiagara
plugin. Public package Node requirements remain as declared in each package; repository release
tooling uses Node 26.

- Clean release pack: passed in 4m06s.
- UAsset engine matrix (UE 5.7 and 5.8): passed in 5m10s.
- Live Unreal gate (check:unreal): passed in 3m18s; 33 tests passed, 0 skipped.
- Plugin compatibility on UE 5.7: passed in 52s.
- Plugin compatibility on UE 5.8: passed in 38s.

Preparation found four problems, each fixed before these runs: the packed graph still required
Game Text's removed `./browser` export; the packed consumer's Effect peer check resolved Game Text
by its removed root; the Data Authoring kit's copy list lacked protocol's `errors.ts` and the
reader's `protocol-path-identity.ts`; and `pnpm check` and `check:unreal` imported package build
output without building it first, which a fresh checkout lacks. No packages or release tags have
been published.
