# UE Shed 0.26.0

UE Shed 0.26.0 decodes far more of what a saved package holds, and reads and scans faster. All 21
public npm packages and twelve Unreal plugins advance together; packages without direct changes
advance for suite alignment and exact dependencies.

Every library change in this release is additive.

## Asset reader

The reader decodes far more saved properties into typed values instead of keeping their raw bytes:

| Project               | Packages | Packages with nothing left raw | Values left raw |
| --------------------- | -------: | -----------------------------: | --------------: |
| Large UE 4.27 project |  167,507 |               64,439 → 140,212 | 654,042 → 1,019 |
| UE 5.7 project        |   11,644 |                 8,216 → 11,453 |    82,023 → 261 |

Newly decoded:

- enum arrays in UE 4.27-era packages, and per-platform values (`PerPlatformFloat`, `Int`, `Bool`,
  `FrameRate`);
- skeletal mesh sampling tables, field paths, delegate bindings and gameplay tag containers;
- material input connections and constants, and the `Vector3f`, `Vector4f`, `IntVector2` and
  `Box2f` math types;
- optional properties and Universal Object Locators;
- Niagara maps, variable records, VM function bindings and shader parameters;
- Landscape layer maps and physics constraint instances;
- formatted text (`FText::Format`) with named or ordered text arguments.

How it decodes:

- Each layout follows the engine's serializer for the versions it accepts, checked against the
  UE 4.27, 5.6, 5.7 and 5.8 sources. A layout that doesn't match keeps its raw bytes at its own
  boundary, so later properties are unaffected. Text formatted with numbers stays raw, because its
  result depends on the locale.
- The reader reuses a property layout it has already checked when the next export of the same class
  has the same bytes, and does less lookup work per property. Parser work on a large UE 4.27
  project's text scan fell by 13–30%. Decoded values are identical.

## Game Text

- Building shared strings and query indexes copies less and runs in parallel, and the scan skips
  work that can't produce text.
- A first scan of a large UE 4.27 project (167,507 packages) takes about 33 s, down from 36 s with
  0.25.0, measured in a host app with the two readers interleaved.
- On that project, packages read only in part fell from 2,061 to 1,452, and text properties the
  reader couldn't decode from 4,336 to 7. Lines found rose from 260,980 to 260,998.
- **Fixed:** text saved as the result of `FText::Format`, such as a graph node's title, a split
  pin's label or a Sequencer track's name, is no longer listed as a line. Unreal doesn't gather a
  formatted result (it has no text ID); its pattern is gathered where it is defined. Listing each
  filled-in result under the pattern's key showed them as **Same key, different text**: on that
  project, conflicting lines fell from 7 with 0.25.0 to 1, the one real case.
- **Fixed:** cancelling a quality check while it prepares its columns stops it within about 25 ms
  and leaves the reader usable. Before, the check ran on until the cancellation watchdog restarted
  the reader.
- For the same reader output, exports, check reports, shared IDs and the snapshot format are
  unchanged.

## CLI

- `ue-shed text search` without `--target` prints at most `--limit` matching lines (50 by default)
  and reports `total` and `omitted`. It used to print every match.

## WASM runtime

- Inspection is about 45% faster on Node 24 and 26, with identical output.

## Benchmarks

- `tools/benchmarks/uasset-decode` gains a coverage census: it decodes every export of every
  package in a list and counts what stays raw, by reason, type, struct and class.

## Unreal plugins

No plugin source changed; the plugins advance to 0.26.0 for suite alignment.

## Compatibility

Use matching 0.26.0 packages and plugin sources. Public package Node requirements remain as
declared in each package; repository release tooling uses Node 26.
