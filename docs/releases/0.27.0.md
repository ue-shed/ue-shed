# UE Shed 0.27.0

UE Shed 0.27.0 adds Quality search and filters, compiled localization resources, native incremental
Game Text refreshes and change tracking. All 21 public npm packages and twelve Unreal plugins advance
together; packages without direct changes advance for suite alignment and exact dependencies.

This release includes source API changes for hosts; see Compatibility below.

## Quality checks

- Search and narrow the Quality list (#209). `WorkspaceQualityRequest` takes `query`, `severities`
  and `fixable` alongside the check filter. Each query word matches the source or the finding
  culture's translation, ignoring case, through the Text tab's native matcher. Source findings
  match their own source text.
- Search, export and suggested fixes share the narrowing. Export presets can carry
  `workspaceNarrowing`, and reports record it. Native `findings_query` gains
  `lines: { text, where }`, timed as its `lines` stage.
- Check counts follow the narrowing. Severity counts now follow the selected check and narrowing,
  excluding only their own severity selection; previously they counted every check.

## Game Text change tracking

- A target's `generation` is its opaque joined key: it changes when packages, localization, review,
  code or policy change, stays equal across unchanged refreshes and can be compared across processes.
  It also changes after compaction. Refresh results, target indexes and workspace results expose it.
- `NativeTextQuery.changedSince` and workspace `changedSince` compare generations by line ID or
  package path, including packages without text. Answers are `same`, `too_old` (with a reason) or
  paged changes and counts, up to 1,000 items per page. The reader caches its diff for paging.
  The native contract adds `changed_since` and its generated request and answer types.
- `diskChanges` compares Content package signatures and a target's localization and review files
  with its index, without writing. Callers can check up to 4,096 named paths or walk the tree,
  with counts, cursors and pages of up to 1,000 items. Sidecars check their package.
  `watchDiskChanges` streams checks through the new `DiskWatcher` service and `DiskWatcherNodeLive`,
  settling bursts for 300 ms by default. The native contract adds `disk_changes` and `JoinedReviewFile`;
  review snapshots carry file provenance, and uasset-io sends the action with contract minor 16.
- Fixed (#204): occurrence moves, additions and removals now count as line changes. Disk comparison
  uses the view's joined layer even after another scan publishes newer shards. Reserved Unicode
  scalars in filenames retain their identity, paths and cursors, ordered by WTF-8 bytes. Watching a
  folder that does not exist yet follows its nearest existing ancestor, so creation triggers a check.

## Localization and review

- Compiled `.locres` supplies translations when a culture has no archive (#205). The native importer
  reads versions 0–3 with display strings and source hashes; version 3 hashes are verified against
  Unreal-compiled resources, while older versions are marked unverified. Malformed resources return
  `malformed_locres` with recovery guidance.
- Resource translations report `translated`, `not_translated` or `needs_update` against the available
  source. A missing entry is `not_translated` with a manifest and `unknown` without one. Shipped
  origins include `locres`, and rules can read `latestOrigin: "locres"`.
- Target discovery finds `Content/Localization/<Target>/<culture>/<Target>.locres` without gather
  configs. Resources join a Dashboard target of the same name or form a `resource_files` target;
  `resourcesDiscovered` and the Workbench's discovered label expose their origin.
- `related` accepts `similarKeys: { limit }` for a target. The engine ranks candidate keys and
  one-to-one pairs with distance, package scope, earlier translations, pair counts, truncation and
  build time. Existing exact pairs and `key_changed` counts remain intact. Hosts can configure
  distance, reach, maximum distance, comparison budget and minimum letters. Generated types and
  tracing expose the result; the reader caches one parameter set per target.
- Change comparisons put failing findings before warnings across all pages, passing `failOn` to
  native `compare_points`. ID repair pages every occurrence beyond the first 500 and refuses a unit
  that changes between pages; related requests accept up to 500 places instead of failing above 50.
- Review flags, accepted findings and staged edits use native `review_lines` in one request per
  culture. `reviewLocalizationChangeSet` accepts those indexed lines. Parsed-file fingerprints now
  choose shipped translations as the join does for duplicate entries or unreadable archives.

## Refresh performance

- Existing indexes update changed package shards in place regardless of how many changed (#202).
  Unchanged records stay native; staging or disk spooling keeps changed records out of the
  JavaScript heap. All changed shards still publish atomically. Initial scans and incompatible
  package formats or audience policies retain the full publication path.
- Progress separates `package_read` (with unchanged counts), `package_update` and `package_publish`.
  uasset-io 1.22 adds `compare_packages`; `publish_packages` accepts `rowsFile` and shards without
  `previousKey`. String domains are interned once per request across all 256 shards.
- Cold and warm localization imports use one native request for changed files. Unchanged stat hints
  avoid reads; warm imports load the dictionary once. A generated 130k-line, ten-culture target
  refreshed 21 rewritten files (712 MiB) in 8.5 s instead of 35.4 s.
- A failed file no longer blocks other imports: each returns a tagged imported/failed outcome and
  diagnostics. The engine owns content keys and drops the `cold` request flag. Stat hints change
  version, causing one reread after upgrading while retained layers avoid parsing. Warm imports
  expose `LocalizationImportProfile` too.

## Runtime and host APIs

- Effect advances to 4.1.2 and `@effect/tsgo` to 0.67.3 (#207). The observability package fixes its
  OpenTelemetry `NodeSdk` import; Electroswag can drop its local patch for that import.
- Effect lint tooling and generated Rust contract types are updated (#200). Additional Effect,
  Schema and comment rules check service operations, schema compilation and suppression reasons
  (#203), with corresponding fixes across the suite.
- Parameterless service operations are reusable Effect/Stream properties: execute
  `yield* ids.generate` instead of `yield* ids.generate()`. Parameterful operations remain functions;
  fresh execution, scopes and tracing are preserved. Progress hooks and comparison layers retain
  supplied error types. Recoverable boundaries preserve tagged failures and causes.
- Hosts construct tagged `GameTextWorkspaceHostFailure` values with the original cause. Supervisor
  resolution exposes `ProcessSupervisorUnavailable`; map-tile and review ports use named error
  unions, including `ReviewCaptureError`. Restoration refusals carry `MapTileCaptureRestorationError`
  and retain ownership until release succeeds. Foreign throws use tagged `UnknownError` where needed.
- Measurement/cache metadata and localization memory budgets reject non-finite values; finite
  fractions remain valid. Package text diff counters require non-negative integers. Source-quality
  hydration preserves host method receivers. Cancelled plugin archive IO settles before resources
  are released, including fiber interruption.

## Unreal plugins

No plugin source changed since 0.26.0; the plugins advance for suite alignment.

## Compatibility

Use matching 0.27.0 packages and plugin sources. Public package Node requirements remain as
declared in each package; repository release tooling uses Node 26.

- Migrate parameterless service implementations and checked-dispatcher adapters to properties;
  see [the migration guide](../engineering/effect-operation-properties.md).
- The former dictionary epoch `generation` on project/target indexes is now `storeEpoch`;
  `GameTextIndexQuery.open` takes `storeEpoch`. Target `generation` now means the joined key.
- Custom watchers take a project root and project-relative folder. Custom host ports must classify
  failures into the exported unions and retain causes and recovery guidance. Native schemas and
  wire representations are unchanged by the service-property migration; use the coordinated
  generated contracts for the new Game Text requests.
