# UE Shed 0.27.1

UE Shed 0.27.1 speeds up Game Text exports and pages and fixes decoding of large localization pages
([#208](https://github.com/ue-shed/ue-shed/pull/208)). All 21 public npm packages and twelve Unreal
plugins advance together; packages without direct changes advance for suite alignment and exact
dependencies.

## Game Text reads

- A localization line export with `fields` builds only the fields it names. Identity and source
  exports no longer construct and discard each line's full preview and every culture's translation
  and marks. Full previews retain their existing values.
- Rows-only pages (`searchRows`, without counts, facets, groups, open groups or a group page) walk
  display order until the requested page and lookahead are filled. They no longer list every match
  before taking a page. Cursor behavior is unchanged, including restarting when its row no longer
  matches. Queries that need every match keep their full traversal.
- Nested batch values, including cultures, manifest entries and places, serialize into one buffer.
  Plain strings copy through with the same escapes; WTF-8 scalar views and lone surrogates retain
  their existing encoding. Nested-cell serialization is about seven times faster and byte-identical.
- Previews cache manifest file metadata once per reader. Column-cache lookups borrow layer and
  column names instead of allocating owned key pairs, using nested Fx hash maps.
- The Quality search added in 0.27.0 retains complete matching through `EngineQuery::matching`;
  its results are unaffected by bounded page traversal. The native contract identity is regenerated
  from the combined sources.

## Localization page fix

`LocalizationQueryPage.lines` now accepts the same maximum as the query request: 100,000 rows.
Previously it rejected more than 50, so an otherwise valid larger `pageSize` failed with
`search_decode`. Regression tests cover admitted bulk requests and rejection above the maximum.

## Measurements

These are #208's recorded measurements, not a new release benchmark. A generated cohort (seed 57)
contained 583,507 lines and ten cultures. Fresh engine processes alternated over two rounds with
three timed repetitions after warmup. Because the machine had other load, native figures below
are minimums in milliseconds; the parked SQLite pilot's figures are medians for reference.

| Read                                 | Before #208 | 0.27.1 read paths | Pilot SQLite |
| ------------------------------------ | ----------: | ----------------: | -----------: |
| All 583,507 lines, identity + source |      21,397 |             3,366 |        5,260 |
| 1,000 chosen lines, all fields       |         671 |               466 |          229 |
| Source page, first 50                |        5.97 |              4.04 |         2.35 |
| Source page, next page               |        3.34 |              1.68 |         2.04 |
| Source page, broad text search       |        3.74 |              2.19 |         1.62 |
| Source page, first 5,000             |         174 |               147 |           94 |
| Target page, first 50                |        13.9 |               9.0 |         14.9 |
| Target page, broad text search       |        20.4 |              12.5 |         15.1 |
| Target page, next page               |        14.5 |               8.3 |         13.8 |
| Target page, first 5,000             |       1,284 |               907 |        1,380 |
| Target search with counts (control)  |        64.9 |              62.4 |            — |

All 268 pilot query cases matched the pre-change engine's answers by SHA-256 in every lane and
round, using the fixed host. Coverage included rows, counts, facets, groups, cursors, aggregates,
details, focus, export and the corpus fingerprint. Full-field chosen-line reads and 5,000-row source
pages remain slower than the SQLite pilot; this release does not claim to close those gaps.

## Unreal plugins

No plugin source changed since 0.27.0; the plugins advance for suite alignment.

## Compatibility

Use matching 0.27.1 packages and plugin sources. Public package Node requirements remain as
declared in each package; repository release tooling uses Node 26. This patch retains the 0.27.0
host APIs and query answers, and expands the host's accepted localization page size to match its
existing request contract.
