# UE Shed 0.28.0

UE Shed 0.28.0 makes Game Text findings rows of the same query engine used by the Text tab,
replacing the one-option-per-filter Quality action with a shared expression and field model. All 21
public npm packages and twelve Unreal plugins advance together; packages without direct changes
advance for suite alignment and exact dependencies.

This release includes breaking source API changes for Game Text hosts and saved investigation
presets; see Compatibility below.

## Findings as query rows

- Findings are selected with `selection.rows: "findings"`. A `where` expression can test finding
  fields (`rule`, `severity`, `culture`, `subject`, `fixable`, `change` and `id`) and, through
  `row`, the finding's Text-tab row. Culture findings use their culture, source findings use their
  unit and line findings use the selection's scope.
- Finding facets count by finding fields or by the corresponding text row's fields. The engine
  combines line and source finding counts before applying the facet limit, so shared values retain
  their complete count and `more` is not double-counted.
- Query fields, groups and facets share one field registry and one name per field. Facets are a
  requested list, and text rows can now be counted by namespace. Finding rows retain the existing
  orders, paging, diagnostics, counts and `findingJson` export.
- The queried workspace, source report and `ue-shed loc check` now read finding rows. Fixture and
  retained-project parity checks covered the requests those surfaces send, including pages, counts,
  facets and the findings sink.

## Shared host filters and presets

- `WorkspaceQualityRequest` takes `where` and `facets` in place of `severities` and `fixable`; its
  page returns the requested facets. `@ue-shed/game-text/query` exports the `QueryExpr` schema and
  the `textWhere`, `qualityWhere` and `rowWhere` converters from host controls to expressions.
- `TextCorpusSearchRequest` also takes `where`, replacing its filter, capability, translator-note,
  location and localization-lens fields. A changed-file list is now `fileScope`. The Workbench,
  CLI and corpus tools use the same converter as external hosts.
- Investigation presets are version 3. They save the `where` and `fileScope` the list runs,
  Quality's search and `where`, and opaque host-owned `controls` that UE Shed preserves without
  interpreting. Earlier preset versions are refused.
- The dedicated native `findings_query` action, `investigationControls` and
  `presetNarrowingRequest` are removed.

## Quality performance

On the retained benchmark project (265,791 lines, 156,637 findings and ten cultures), reading a page
now orders only that page's lines instead of building occurrence order for the entire corpus. The
measurements below are isolated single runs against published 0.27.1, so they are directional rather
than medians. The final Quality requests include the shared toolbar's five facets.

| Path                                   |     0.27.1 |     0.28.0 |
| -------------------------------------- | ---------: | ---------: |
| First Quality page after opening       |   2,825 ms |     613 ms |
| Duplicate badge request                |   2,834 ms |       none |
| First Quality search                   |   2,478 ms |     446 ms |
| New search with no match               |     149 ms |      97 ms |
| Severity, folder or suggested-fix pill |   39–62 ms |   20–97 ms |
| Text-tab search                        | 247–285 ms | 219–281 ms |

The duplicate badge request is gone; the list's own count supplies it. The Text tab remains within
the baseline's run-to-run range.

## Unreal plugins

No Unreal plugin source changed since 0.27.1; the plugins advance for suite alignment.

## Compatibility

Use matching 0.28.0 packages and plugin sources. Public package Node requirements remain as
declared in each package; repository release tooling uses Node 26.

- Replace `findings_query` calls with query selections whose rows are `"findings"`.
- Convert Text and Quality controls to `where` with `@ue-shed/game-text/query`, request the facets
  each surface needs and read them by field name from the answer.
- Replace Text request `filter`, `capability`, `withoutNotes`, localization-lens and location
  fields with `where`; use `fileScope` for a changed-file list.
- Recreate investigation presets in version 3. Versions 1 and 2 are intentionally not migrated.
