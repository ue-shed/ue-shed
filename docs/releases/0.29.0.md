# UE Shed 0.29.0

UE Shed 0.29.0 fixes state that outlived its owner across the host, Game Text, the parsers and the
Unreal plugins. Late completions, superseded writers, recycled buffers and paused runs could
otherwise act for an owner that had moved on. All 21 public npm packages and twelve Unreal plugins
advance together; packages without direct changes advance for suite alignment and exact
dependencies.

This release includes one breaking source API change for camera setup hosts, and Map history
requires p4client-ts 0.15.0; see Compatibility below.

## Host and Workbench ownership

- Late completions keep their owner: a project opened later stays selected, a newer rules
  selection survives an older save, and scan progress belongs to the logical scan that started it.
  A refused oversized scan request leaves the running scan's progress and ownership alone.
- Custodian receipts are persisted for cancelled and approved proposals. A native reader worker
  that exits between requests is replaced.
- Camera sessions: approved review sessions stay unchanged by later previews or world changes.
  Provisioned bindings are invalidated after a map open. A failed detach keeps its diagnostics for
  retry. Discarded provisioning no longer renders a stale session.
- Editor targets, command status, content-history cancellation and project launches serialize
  their transitions, so an overlapping reset, poll or launch cannot replace a newer one.
- A supervised editor session accepts readiness only from the editor it launched. Another editor
  already on the Remote Control port is refused, and the launched one is cleaned up.
- A persistent native reader request's write is bounded by its deadline and cancellation, so a
  worker that stops reading no longer holds a request open.

## Game Text

- Pending translation writes survive copying file lists. ID-repair ownership and receipts survive
  a refresh of the focused text, and carried translations stay with the target submitted with
  Apply.
- A culture's compiled resource is imported when its archive disappears during a refresh, instead
  of the culture reading as absent or from an older resource.
- A finding accepted on a culture backed only by a `.locres` stays accepted. Such findings now load
  in the CLI quality report and the workspace, with `translationOrigin: "locres"`.

## Parsers and indexes

- The package parser checks an outer chain's depth before following it. A malformed package with a
  long chain now fails with a parse error instead of exhausting the native or WASM stack.
- A Blueprint diff treats a construction script that lost a component node as unread. It no longer
  reports false component additions or removals.
- The source-text wrapper scan caches a set only from a scan that listed every folder. Wrapper
  caches written by earlier versions are read again once.

## Cameras, history and observation

- A visibility-policy change advances the View revision, so captures of the old revision no longer
  read as current.
- Map history: a project tree that a failed revision left mixed is refused until rebuilt. The
  baseline budget counts distinct files across scopes. Concurrent revision-cache writes each stage
  their own file. Playback frames after a partial snapshot read as partial.
- Actor observation leaves live, keeping the last sample, when Unreal's writer closes without a
  reset, then recovers. The previous session's writer closing late does not end the new session.

## Unreal plugins

- **Cameras:** a readback poll is bound to its capture's generation, with at most one poll queued
  per slot, so an older poll cannot copy an earlier capture into a slot reused for a later one.
  Final renders rescan editor-preview children before each frame, so a child rebuilt while settling
  appears in the final image.
- **Camera authoring:** the arrangement panel is read-only until it shows the revision and camera
  Unreal applied. A typed value waits instead of being dropped.
- **Scenarios:** a run that holds live-input isolation for longer than its duration plus its wait
  timeout plus 30 seconds of real time ends as `cancelled` with `ownership_timeout`, including while
  PIE is paused. The input isolator is removed once.
- **Game Text:** the commandlet writes its result and manifest to a temporary file and renames it
  over the target, so a reader never sees partial JSON.

## Compatibility

Use matching 0.29.0 packages and plugin sources. Public package Node requirements remain as declared
in each package; repository release tooling uses Node 26.

- Camera setup hosts must call `poll(bridge, projectName, { projectRoot, endpoint })`. The context
  scopes saved-set listings and acknowledgement outcomes to one project and editor, including when
  bridge adapters are recreated between polls.
- `@ue-shed/map-history` depends on `p4client-ts` 0.15.0. Its 0.14.0 errors are branded and its raw
  rows typed; a host that builds p4client-ts values for Map history must use 0.15.0's types.
- `ActorFeedApi` gains `connections` and `writersLost`; a custom feed implementation provides both.
  `makeActorFeedTestLayer` supplies defaults.
- Localization quality findings may report `translationOrigin: "locres"`. A host that switches on
  the origin should treat it like `"archive"`: the translation the game uses.

- UAsset engine matrix (UE 5.7 and 5.8): passed in 8m39s.
- Live Unreal gate (check:unreal): passed in 5m39s; 33 tests passed, 0 skipped.
- Plugin compatibility on UE 5.7: passed in 1m06s.
- Plugin compatibility on UE 5.8: passed in 2m51s.

The first preparation run failed three gates. The check and pack gates failed because the pack
graph still required Map history's previous p4client-ts pin, fixed in the release commit. One Workbench end-to-end case failed in the
live Unreal gate: the second of two back-to-back FOV edits was refused as a stale revision before
the renderer saw the first. The 37-camera case of the same journey passed in that run, and every
case passed on the rerun above.
