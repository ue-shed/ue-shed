# UE Shed 0.3.0

UE Shed 0.3.0 deepens the reusable capture, saved-world, and process-ownership primitives needed
by supervised downstream producers. All 15 public npm packages use the same 0.3.0 version. The
packages without a direct behavioral change are republished for suite alignment and exact internal
dependency pins.

## Highlights

- Review Capture and Map Capture accept caller-owned final destinations through prepared storage
  adapters while preserving their project-local defaults and Unreal staging beneath
  `Saved/UEShed`. The adapters retain containment, exclusive attempt creation, atomic publication,
  cleanup, and each workflow's distinct completeness rules.
- Saved-world output exposes finite effective location, quaternion rotation, scale, and direct
  root-component attachment evidence. Resolution failures remain explicit for missing roots or
  parents, cycles, ambiguity, non-finite values, and unsupported absolute transforms.
- Map History schema version 2 records the expanded saved actor shape and distinguishes movement,
  effective-transform, attachment, and transform-resolution changes. Equivalent quaternion
  representations do not create representation-only history events.
- `@ue-shed/engine` adds an Effect-scoped supervised Unreal Editor session with typed readiness,
  cancellation, exit, and teardown outcomes. The existing detached interactive launcher keeps its
  prior meaning.
- New `@ue-shed/engine-win32-x64` supplies the Windows x64 Job Object supervisor used to retain and
  terminate only the process tree owned by a scoped editor session.

## Compatibility notes

- The `unreal-saved-world` wire contract advances from version 1 to version 2. Consumers of
  `@ue-shed/uasset`, `@ue-shed/uasset-win32-x64`, `@ue-shed/unreal-assets`, or
  `@ue-shed/protocol` saved-world output must accept the version 2 actor transform and attachment
  shape.
- Map History documents advance to schema version 2 to carry the versioned saved actor evidence.
- Caller-owned capture destinations and scoped editor sessions are additive APIs. Existing
  project-local capture repositories and detached editor launching remain supported.
- Bounds, Data Layer membership, and caller-selected property evidence are not claimed in this
  release because the available saved-package fixtures do not yet prove truthful generic
  projections.
