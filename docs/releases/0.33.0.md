# UE Shed 0.33.0

UE Shed 0.33.0 delivers major performance and memory improvements across Project Index, Game Text,
and the Rust UAsset parser, plus incremental Project Index refreshes, NTFS change journal support
on Windows, and union/projected header queries (uasset-io v1.26 and v1.27). All 21 public npm
packages and twelve Unreal plugins advance together. Packages with no direct changes advance so the
suite stays aligned and the exact dependency pins match.

## Project Index: incremental refresh, NTFS change journal, and lazy queries

- **Base+delta snapshots and `changedPaths` (uasset-io v1.26)**: A small refresh writes a delta of
  changed entries over the committed snapshot and compacts once the delta grows past 16,384 entries
  or 5% of the index. Callers with file-watcher events can pass `changedPaths` so refresh checks
  only those files and their sidecars, falling back to a full walk whenever paths alone could miss
  a change. Complete summaries carry `inventoryDigest` (SHA-256 of every inventory fact), and
  refreshes run in a persistent worker session that stays warm between edits.
- **Unprivileged NTFS change journal on Windows**: When a refresh is given no `changedPaths` (cold
  start or after a missed watch/sync), each generation records its NTFS USN journal cursor via the
  isolated `fast-fs` crate and reads only changed content directories without administrator rights.
  On a project of about 800,000 packages, an unchanged refresh drops from about 1 s and 150 MB to
  about 30 ms and 24 MB, and a one-file edit from about 1.3 s to about 40 ms. Falls back cleanly
  to a full walk (reporting `walked_because`) on other platforms/filesystems, journal resets or
  wraps, directory renames/moves/deletes below a content root, changed roots, or more than 4,096
  changed directories.
- **Lazy chunk-indexed inventory and lower peak memory**: Snapshot row indexes record per-128-row
  chunk checksums and map row offsets so inventory, map, class, and name queries decode only
  matching chunks (first inventory/map page drops from ~120 ms to <10 ms; first class/name page
  from ~160 ms to 30–45 ms on ~800,000 packages). Streaming snapshot writes, header-worker string
  interning, prefix-shared `SignatureArena`, slim `HeaderIndex` tables, and `MIMALLOC_PURGE_DELAY=0`
  (when unset) substantially cut build and refresh memory.
- **Union queries and field projection (uasset-io v1.27)**: Adds `ProjectIndexQuery.cases.Union`
  (up to 16 header filters paged once each in path order) and optional `fields` selection
  (`classes`, `serializedNames`, `matchedSerializedNames`, `headerData`). Dictionary page frames
  validate in one walk, expand in one pass, and decode record blocks across threads (on ~800,000
  packages, a five-filter sweep drops from ~410 ms to ~210 ms, or ~170 ms with 6.8 MB vs 17.1 MB
  wire payload as one projected union).
- **Retiring SQLite Catalog oracle**: Replaces the SQLite Catalog oracle with an in-memory
  differential test and drops the `rusqlite` native dependency.

## Game Text: 3.1× faster cold preparation, delta planning, and snapshot/PO polish

- **Parallel scan, join, and extraction**: Parallelized `extract_text_packages` and `join`,
  streaming package-text extraction, heaviest-first (LPT) shard staging to cut worker tail wait,
  surrogate-preserving `join.meta` decoding, and O(1) warm-open witness reuse.
- **Catalog change log and delta shard planning**: Catalog commits maintain a bounded atomic
  `changes.json` log (up to 32 generations / 16,384 paths / 16 MiB). When an unbroken digest chain
  covers the witness digest to the current digest and affects at most 32 shards, `try_plan_delta`
  rekeys only affected shards via targeted `package_text_entries` lookups—resolving sidecar edits
  case-insensitively to exact Catalog package paths and short-circuiting immediately to a full plan
  if the 32-shard budget is exceeded.
- **In-memory snapshot writer and single-pass `.po` decode**: `snapshot::Writer` buffers sections
  in memory up to 32 MiB before spilling to a temp file, runs structural validation before writing
  durable files, and avoids redundant post-write decompress-and-reread passes in release builds.
  Localization `.po` decoding now runs in a single pass with identical escape semantics, and
  localization imports canonicalize each distinct `project_root` once per batch.
- **Measured impact**: On a project of about 780,000 packages (~10,800 text-bearing packages), cold
  Game Text preparation drops from about 41.5 s to 13.2 s with bit-exact output parity and unchanged
  `UESHT004` format compatibility.

## UAsset parser hot paths

- **Faster decoding with unchanged output**: Adds container struct replay, reusable decode session
  tables (honoring dynamic schema providers and per-decode omission policy), optional filtered
  record omission, zero-allocation property tag fast-skip, lean `EdGraphPin` decoding, and in-place
  package path normalization.
- **Measured impact**: On large Blueprint and level packages, cuts allocated bytes by about 31%,
  peak live memory by about 20%, and decode time by about 16% while passing UE 4.27, UE 5.7, and
  UE 5.8 conformance.

## Compatibility

Use matching 0.33.0 packages and plugin sources. Each public package's Node requirement is
unchanged.

- Project Index cache moves to `catalogs-v10`; the first refresh rebuilds it cleanly.
- Project Index `changedPaths` and `inventoryDigest` require uasset-io v1.26; `Union` queries and
  header `fields` projection require uasset-io v1.27, both shipped in this release's native reader.
  Against workers older than v1.27, header queries with `fields` read all fields and filter in the
  adapter, while `Union` fails with `ProjectIndexIncompatibleWorker`. Header items in v1.27 pages
  may omit `classes` and `serializedNames` when excluded by `fields`.
- Game Text snapshot format (`UESHT004`) is unchanged.
- Unreal plugin behavior and wire contracts are unchanged; plugin descriptors advance to 0.33.0 for
  suite alignment.
