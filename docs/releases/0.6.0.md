# UE Shed 0.6.0

UE Shed 0.6.0 expands saved-project inspection and headless investigations, improves Project Index
performance, and adds Lit map capture and richer Niagara review workflows. This release follows
0.5.1 and advances all 17 public npm packages and seven Unreal plugin descriptors together.

## Saved-project inspection and investigations

- Inspect saved Blueprint graphs without launching Unreal. The public `readSavedBlueprint` API,
  native reader, and WASM inspection expose graph and node identities, saved positions, typed pins,
  defaults, links, tagged properties, and coverage diagnostics. Workbench adds graph browsing and
  search. This is read-only inspection of supported uncooked packages, not compilation or execution.
- Profile DataTables with `ue-shed authoring analyze` and the Workbench Charts view. Filtered rows
  drive distributions, numeric histograms, grouped averages, and numeric scatter plots.
- Save Game Text investigation presets and replay them against an explicitly selected project with
  `ue-shed investigations run`. Complete filtered JSON/CSV exports retain text identities,
  occurrences, quality rules, coverage, and provenance independently of UI pagination.
- Browse saved Niagara Systems before starting capture. Saved-project discovery remains usable
  without a running editor.

## Project Index and Workbench

- Immutable binary Catalog snapshots replace the production SQLite catalog. Batched header
  observations, parallel discovery, indexed postings, compact query transport, and reuse of
  validated pages improve fresh scans, refresh, and startup. Writer exclusion and interruption
  recovery protect catalog publication; SQLite remains an opt-in comparison oracle.
- `countProjectIndex` provides generation-bound counts for map, class, prefix, suffix, and serialized
  name filters without transferring candidate headers. Overlapping matches count each package once.
- Saved-world Scout gains a GPU-backed point map. Shared actor tools add search, selection, framing,
  and catalog metadata, while saved-world loading and capture expose more useful progress.
- Workbench improves retained investigation state, project-generation race handling, virtualized
  actor keyboard access, and Windows process-supervisor resolution.
- A headless selected-target service captures the Unreal endpoint for each operation and its child
  work. Changing targets affects subsequent operations. Camera/world contracts and metrics helpers
  gain browser-safe entry points.

## Map Capture and Niagara

- Lit editor-camera tiles become the default Map Capture backend, with shared exposure, disabled
  vignette, plugin-owned scene freezing, asynchronous capture, and cancellation cleanup. Manual
  exposure is optional; explicit legacy backends remain available. New plans use 16-pixel gutters
  and disable fog.
- Library and CLI inspection can report capture selection bounds and Lit readiness before capture.
  Optional producer/plugin identity, actor metadata, and structured progress improve diagnostics.
- Niagara review profiles add lit isolated scenes, automatic camera fitting, explicit camera
  overrides, and matched dark/light backgrounds. Auto-fit and explicit overrides can capture
  systems without a saved Baker camera; saved-camera transparent capture remains available.
- Activity-window and poster helpers, material diagnostics, and a local FFmpeg encoder produce
  derived video from verified preview evidence. Encoder inputs are snapshotted after verification.
  Capture progress covers initialization, compilation, fitting, frames, and receipt publication.

## Upgrade notes

- Existing Project Index caches rebuild on first use. Native source builds require Rust 1.89.
- Update Unreal plugins alongside the npm suite. Default Lit map capture requires the updated
  Cameras plugin and an unlocked rendering editor viewport. New inspection operations require the
  advertised Core/Cameras capabilities.
- Niagara request, receipt, and run contracts advance to 1.2. Readers retain 1.0/1.1 support, but new
  capture requests require the matching 1.2 producer. Older producers may omit optional progress
  and metadata where their existing operations remain compatible.
- Niagara's isolated preview scene does not reproduce map collision, depth, gameplay drivers, or
  external user parameters. Map-backed capture remains outside this release.
- Saved Blueprint inspection supports the documented UE 5.7 saved-revision window; cooked packages,
  Control Rig's separate RigVM model, referenced-package loading, and mutation remain unsupported.
- Public npm packages retain Node.js 22.14 as their declared minimum. Repository builds use Node.js
  26 and the TypeScript 7 native toolchain; a replacement packed-consumer Node 22 CI lane is pending.
- Packages without direct changes advance solely for suite alignment. See each package's changelog
  for direct changes and dependency updates.

## Release preparation

The release source is based on `def7219`, compared with tag `v0.5.1`. Publication requires a reviewed,
clean release commit, the portable `pnpm check` gate, and trusted `pnpm check:unreal` evidence because
this release changes native inspection and Unreal plugin behavior. Source bundles and compiled
variants must be bound to that exact release commit; preparation alone does not publish artifacts.

See [the release procedure](../engineering/releases.md) for packing, evidence, and publication.
