# UE Shed 0.8.0

UE Shed 0.8.0 adds actor-scoped camera authoring, shared world preparation, and expanded
source-derived saved-asset inspection. All 18 public npm packages and ten Unreal plugins advance
to 0.8.0 together; packages without direct changes advance for suite alignment and exact dependencies.

## Camera authoring and capture

- Create persistent camera arrangements from actor selections, edit transient cameras in Unreal,
  and save reviewed views into shared Review Sets. Native authoring supports selection, piloting,
  duplication, deletion, Undo/Redo, framing controls, and bounded exposure adjustments.
- Use public library and CLI operations independently of Workbench. The native authoring bridge
  and reference menu remain separately enabled integrations.
- Recover abandoned writer locks and interrupted native edits with revision checks. Concurrent
  approvals preserve disjoint changes, and repeated approvals reuse equivalent capture profiles.
- Capture Pure, Authored, or paired visibility outputs. Initial exclusions support loaded opaque
  non-Nanite static meshes; unsupported geometry and unresolved references report explicit failures.
- Workbench defaults final Review capture to high-resolution viewport screenshots and exposes the
  effective renderer, exposure, and settling policy. There is no silent renderer fallback.
- Live previews correlate frames with their provisioned camera identity. Background ticking is
  scoped to active streams, and render leases begin their renewal window after synchronous setup.

## Shared world preparation

The new `@ue-shed/world` package and `UEShedWorld` plugin provide unloaded actor planning, actor
context regions, selective editor loading, Data Layer ownership, bounded renewable leases, and
explicit readiness and recovery operations. Prepared camera capture composes these public services.
The CLI exposes the same preparation operations. Readiness is a single poll named `checkReady`;
callers retain control over waiting and cancellation.

## Saved assets and editor workflows

- Source-derived Unreal class and serialization models now drive supported saved-asset decoding.
  Native and WASM readers share expanded inspection of rich curves, Skeleton reference poses,
  Sequencer channels, bounded InstancedStruct values, StringTable metadata, and package metadata.
  Saved string-table text identities are preserved; unsupported inner payloads remain explicit.
- Editor map opening supports asynchronous operation identities and completion polling without
  replaying commands after lost acknowledgements. Workbench verifies the editor project root before
  synchronizing or switching maps and offers saved-review-only browsing.
- Explicit Unreal handoffs activate the connected editor window with verified process identity.
  Workbench adopts Solid 2 and preserves keyboard focus across virtualized actor-list updates.
- Source-engine plugin builds target requested modules while retaining engine build identity and
  useful launch diagnostics.

## Upgrade notes

Install matching 0.8.0 packages and native plugins. Map Review now requires **Core, World, and
Cameras**; native camera authoring remains optional. Update Core to enable project-verified map
synchronization. Older companions without project identity cannot synchronize or switch maps.
UE 5.8 launch permissions include the separately enabled World Remote Control API.

Native plugin compatibility covers Unreal 5.7 through 5.8.2. Saved-asset conformance remains scoped
to supported UE 5.7 fixtures; native plugin compatibility does not extend saved-package format
coverage. Compiled variants still require matching engine version, BuildId, platform, and architecture.

## Validation

conformance for all 18 public packages. The trusted Unreal gate also passes. Native compatibility coverage includes all ten plugins and
19 automation tests on both stock Unreal 5.7.4 and 5.8.2. Live Review coverage includes the
37-camera capture and restart journey.
