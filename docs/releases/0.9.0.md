# UE Shed 0.9.0

UE Shed 0.9.0 polishes the native Unreal camera panel, decodes saved Blueprints, Level Sequences and
DataTables in the browser, and deepens saved Blueprint and Sequencer inspection. All 19 public npm
packages and ten Unreal plugins advance to 0.9.0 together. `@ue-shed/blueprints` publishes for the
first time; packages without direct changes advance for suite alignment and exact dependencies.

## Native camera panel

- Open the panel from **Window → Cameras (UE Shed)** in the Level Editor section as a short
  **Cameras** tab. **Select** frames a camera with its subject, or switches the pilot while piloting.
- **Save views** is the primary action, and the footer counts views that are not saved yet. Numbers
  and the Visibility page use plain wording instead of raw values.
- Every preview tile and camera-list row says whether its shot shows the subject (visible, partly
  hidden, blocked, not in the shot or didn't render), measured with the Review capture's depth
  comparison. Camera-list rows show thumbnails from the same preview renders.
- The setup page lists the selected subject's saved sets and can reopen one in the host.
  `makeCameraSetupHost` accepts optional `open` and `sets` callbacks; the camera-authoring/v1 setup
  contract gains optional reopen fields and the `setup_open` request.
- Camera render policies accept opt-in `renderer.editorPreviews`. Viewport and SceneCapture renders
  then show child actors spawned for editor-only owners, such as spawn-volume previews, while other
  editor-only content stays hidden. The plugin restores the original flags when the session ends,
  fails or its world is cleaned up, and saves never write the changed flag. A Review capture run
  that picks another renderer keeps the saved `editorPreviews` setting.

## Saved assets in the browser and Workbench

- The website decodes a dropped `.uasset` in a module worker through WASM; nothing is uploaded.
  `/inspect` shows typed property trees, string tables, DataTables, skeletons and enums, and hands
  graph-displayable assets to the `/blueprints`, `/sequencer` and `/data-tables` viewers.
- Workbench uses the same viewers through the native reader. Blueprints and Sequences open by
  searching the scanned project. The Blueprint viewer, Sequencer timeline and Data Authoring use
  compact summary rows and a light-blue accent.
- `extractAuthoringTable` exports bounded DataTable authoring snapshots from the portable
  inspection projection. Native authoring JSON is unchanged.
- DataTable authoring, typed saved inspection, and the text, texture and saved-world wire models
  move from the IO layer into the portable inspection layer that native and WASM share. IO keeps
  file reads, scanning, cancellation, protocol framing and failure mapping. Native output is
  byte-identical, and no NDJSON or TypeScript protocol schema changed.
- The new `@ue-shed/blueprints` package provides headless saved-graph indexing, navigation, bounded
  search, reference layout and display metadata. The Solid viewer stays in Workbench.
- Data Authoring uses `peculiar-sheets@0.15.0`, built for Solid 2 RC 9, which restores inline grid
  editing without a local patch.

## Saved Blueprint and Sequencer inspection

- The public reader, CLI and Workbench add typed Level Sequence reads, reference inventory and
  resolution, and bounded comparisons that report incomplete evidence explicitly.
- Level Sequence schema 4 adds saved scalar float/double and 3D transform channels; schema 5 adds
  bool, integer, byte/enum and visibility channels; schema 6 adds shared section settings, scoped
  camera cuts, binding metadata and string/object channels.
- Blueprint schema 2 adds variable declarations, saved CDO overrides, component hierarchies and
  templates, and source-checked inherited actor/component native records.
- The shared native layouts decode property bags, GameplayTagContainer and common math
  properties, and produce saved animation summaries.
- Keyed FText and StringTable entries saved by UE 5.8 keep translator notes as `dev_notes`; Game
  Text exposes them on each `TextOccurrence.devNotes`.

## Dependency security

- Workbench requires Electron 43.5.0 or later and locks 43.7.7, covering the open sandbox,
  protocol-handler, webview and
  preload-cache advisories.
- Vitest and its coverage package advance to 4.1.11. Transitive dependency floors require Undici
  7.29.1 / 8.10.2, Sharp 0.35.4, Browserslist 4.28.7, baseline-browser-mapping 2.11.0 and NanoID
  3.3.18. PostCSS remains at the patched 8.5.23 floor. The workspace audit reports no known
  vulnerabilities.

## Release fixes

- Niagara auto-fit ignores invisible half-float background variation when measuring coverage,
  avoiding a false clipped-frame error for very small effects.
- Saved Blueprint and Level Sequence fixture generation loads existing packages before reuse or
  replacement, allowing conformance checks to run repeatedly in an existing checkout. Failed fixture
  steps now identify the affected generator.
- Conformance verifies committed fixtures without regenerating their saved identities, accepts the
  added translator-note fields, and refreshes level coverage counts. Animation curve evidence uses
  case-insensitive name identity.

## Upgrade notes

Install matching 0.9.0 packages and native plugins. Cameras, Camera Authoring and the Camera
Authoring Bridge changed natively. Older plugins reject `renderer.editorPreviews`, and the renderer
reports `unsupported_capability` before opening a session. Older hosts and plugins are unaffected
by saved-set reopening: the bridge adds reply fields only for hosts that send `reopen: true`.

Consumers of saved Level Sequence records upgrading from schema 3 must accept the new track kinds
and required channel arrays. Blueprint consumers must accept schema 2.

Native plugin compatibility targets Unreal 5.7 and 5.8; this release's UE 5.8 verification is still
required. Compiled variants require matching engine version, BuildId, platform and architecture.
