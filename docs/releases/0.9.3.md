# UE Shed 0.9.3

UE Shed 0.9.3 identifies stale Remote Control plugins on buildable Windows source engines so
hosts can offer a targeted rebuild. All 19 public npm packages and ten Unreal plugins advance
to 0.9.3 together; packages other than `@ue-shed/engine` have no direct behavioral change and
advance for suite alignment and exact dependencies.

## Structured recovery information for hosts

- Project launch validation reports `engine_plugins_stale` when Remote Control dependencies
  have module BuildIds that differ from the engine, their binaries exist, and the engine has
  Build.bat and UBT source without an installed-build marker.
- The error includes `enginePlugins` with the engine root, stale plugin names and buildability.
  Hosts can use these fields to offer a rebuild without parsing diagnostic strings. UE Shed
  does not start a build automatically.
- Missing plugins or binaries, invalid module manifests and installed engines retain the
  existing `plugin_unavailable` failure and manual recovery guidance.

## Upgrade notes

Use matching 0.9.3 packages for suite alignment. Hosts that switch exhaustively on launch failure
codes should handle `engine_plugins_stale`. Native plugin behavior is unchanged from 0.9.2.

Native plugin compatibility targets Unreal 5.7 and 5.8. Compiled variants require matching engine
version, BuildId, platform and architecture.

## Validation

Release preparation on 2026-10-07 uses Node 26.10.0 and pnpm 11.17.0.

- Portable gate (`pnpm check`): passed, 1,550 tests passed and 50 explicitly gated tests skipped;
  all 19 packed packages passed clean offline consumer conformance. Data Authoring adoption
  conformance also passed.
- Trusted Unreal gate (`pnpm check:unreal`) on UE 5.7: passed saved-asset conformance, 13 native
  coverage tests, authoring mutation, Niagara rendering, 22 capture integration tests and five
  Map Review end-to-end tests. The gate cleaned up its fixture editor; generated tracked fixture
  assets were restored after verification.
- Remote Control plugin validation passed against installed UE 5.7 and UE 5.8.
- The targeted source-engine recovery was verified through Electroswag on UE 5.8.2: a staged
  stale manifest produced the recovery dialog, the targeted build repaired it, and Unreal
  launched with the tools and a responding Remote Control server. Cancellation and running-editor
  refusal were verified, and the manually edited manifest was restored byte for byte.
- The full trusted fixture gate uses the committed UE 5.7 contract. It was not run on UE 5.8;
  UE 5.8 verification covered the affected plugin validation and source-engine recovery.
