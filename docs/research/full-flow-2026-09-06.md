# Full project flow performance — 2026-09-06

This pass improves fresh scans, warm refreshes, query processing, and actual Workbench startup.
The production Catalog remains a Rust binary snapshot with no database runtime dependency.

## Baseline and method

Baseline: `ee6d2b30e374fe05ecbea0f02e7886034572a446` on `perf/sqlite-next`. This report accompanies the full-flow optimization commit.
Windows x64, Ryzen 9 7950X, 32 logical CPUs, 64 GiB RAM, Rust 1.94.0, Node 26.5.0.
Small is the checked-in fixture (71 packages, 4 maps); medium has 10,128 packages and 59 maps;
large has 199,539 packages and 257 maps. Private roots were read-only and are omitted from evidence.

Fresh means an empty Catalog, **not a cold filesystem cache**. Timing blocks ran serially without
compilation or tests. Small and medium have three timed samples per state; large has six, with one
untimed warmup per state in the headless benchmark. Results below are medians, not guarantees.

The baseline native executable is the frozen HEAD build. Seven baseline runtime modules were
restored from HEAD to rebuild the original assets adapter and Workbench. Additive v1.4 protocol
schemas and client-only extension exports were shared between builds. Current sources were then
restored and rebuilt. User icon changes were preserved in both builds.

[Raw evidence](full-flow-2026-09-06.json) includes samples, intermediate experiments, executable
hashes, source hashes, parser fingerprints, parity hashes, and packaged-artifact checks. Scratch
executables and logs are under ignored `test-results/full-flow-2026-09-06/`.

- `base.exe`: 4,890,112 bytes; SHA-256 `6c13d2b3110a83747bf408973b6c95c9a8168596b3ac7fc6702fa9c49eedb5f1`.
- `retained.exe`: 4,947,968 bytes; SHA-256 `ec8312431a84c1e7092b463df6f9066f850762e1f467edd46a75cfcfbba17872`.

## Retained changes and experiments

- Sixteen header workers, bounded by available parallelism and the existing total queue capacity.
  Eight → sixteen improved fresh scanning; thirty-two regressed (3.88 s exploratory large median).
- Borrow unnumbered parser names while constructing import/export paths, avoiding temporary clones.
  Numbered names, Unicode, and invalid-index diagnostics retain their existing behavior.
- Validate shared dictionary strings once before expansion, then retain the deeply frozen validated
  page. Structural/domain limits and invalid references remain checked. The first schema variant
  repeated numeric refinements and regressed; the narrower checked-reference variant was retained.
- Use a bounded flat posting union and group nearby header records into page-local read windows
  (up to 256 KiB, gaps at most 4 KiB). Every posting and selected record still receives integrity
  checks. No decoded cache survives a query, preserving detection of later corruption.
- Stream integrity verification of the two large on-demand sections through a 1 MiB buffer.
  A paired eight-run status probe improved from 118 to 111 ms and reduced temporary memory.
- Sort staging observations once and merge sorted prior/current inventories for refresh comparison.
  Borrowed hash lookups were an intermediate improvement; the final linear comparison improved
  warm refresh further. Enumeration is explicitly sorted so arbitrary scanner order remains valid.
- Correct sidecar-only deletion: the no-op snapshot predicate now also checks observed inventory
  size. Removing a sidecar publishes the reduced inventory without claiming a removed package.
- Add headless protocol 1.4 `project_index_count`: count the union of 1–16 bounded filters within
  one pinned generation without hydrating headers. Overlaps count once. The default adapter uses
  paged queries as an independent oracle; production binary storage uses inventory IDs.
- Use those counts for the four Workbench home badges, which previously materialized entire
  candidate corpora. Full candidate queries remain available when features need their evidence.
- Lazy-load 13 renderer routes and import extension clients through client-only entry points.
  The headless core retains all scanning/counting/query capabilities independently of Workbench.
- Reject an exact-root path normalization shortcut: its large trial was 3.23 s fresh / 550 ms warm
  versus 2.71 s / 538 ms for the preceding merge variant. It added a second path without a measured win.

Intermediate blocks are exploratory, not additive speedup claims. Final medians above include all
retained changes together and can be less dramatic than an isolated favorable block.

## Stopping point

The measured opportunities above are implemented and checked. Remaining ideas require more evidence
or larger contracts: filesystem journal/watch reconciliation with fallback recovery; parser resume
checkpoints that safely bind a summary to the same input; direct packed IDs through query transport;
and changed-snapshot persistence that avoids rewriting the complete physical snapshot.

The header profile still shows substantial filesystem opening/signature work. Its worker timings
overlap and cannot be summed into wall time. The slower final input-decode block has not been
attributed to a specific code hotspot. Increasing concurrency further and the extra path shortcut
did not earn their cost.
This is the point to stop adding speculative complexity, with reproducible baselines for the next
workload-driven investigation.
