## Top 5 risks

These are prioritization judgments drawn from the linked evidence, not additional measurements.

1. **Large native data cost:** a one-cell edit on 10,000 rows takes about two seconds. Full snapshot polling also costs about 0.9 seconds. A live large-table authority cannot simply invoke the current full-table RPC on every keystroke.
2. **Background editor progress:** ordinary editor throttling pushes small edits to about 336–341 ms. Disabling the checkbox is insufficient when minimized. T15 proves a native foreground-process lease can exempt this path while preserving the setting; actual Workbench focus/session wiring and first wake still need verification.
3. **Native editor correctness:** current Apply omits the notifications an open table editor needs. The row-list workaround was demonstrated, but add/remove/rename with active row controls can require prechange pointer release and transaction overlap fencing.
4. **Observation/provenance completeness:** raw writes evade hooks; native row payloads omit row identity; canceled changes lack finalization; own Apply lacks request provenance. Echo filtering must preserve later undo and handle reload/reinstancing, reentrancy and missed-event recovery.
5. **Localization authority scope:** immediate display preview, persistent translation files, compiled resources and Unreal undo are different state systems. Source-only preview ingredients and successful commandlets do not prove a unified Level 3 transaction writer; current private translation writing also conflicts with no-checkout policy.

## Things I could not test and why

- **Actual focused timing:** Win32 foreground activation failed on both engines; native state showed Search in foreground. All requested focused benchmarks are relabeled visible/unfocused. Normal policy was tested without -unattended separately.
- **Human widget operations:** automated C++ used editor APIs and inspected cached Slate text; no genuine mouse slider, DataTable row control, active edit pointer lifetime or pixel repaint test. Manual steps are in T08/T12. Modal/PIE/map overlap and native transaction interleaving were not attempted within the research run.
- **Generic network push / recovery:** RC preset push was checked in both engine sources and official docs, not subscribed live. No custom push protocol, resubscription after replacement, dropped-message recovery or two-client runtime race test was built.
- **Cached or no-change Apply correlation:** benchmark no-op is a probe early-return function. It does not establish native event behavior for unchanged mutations or replay of cached receipts; a confirmation design must handle successful receipts without assuming a new object event.
- **Concert replay / public bridge reuse:** source-only study; no Multi-User session or dependency adoption experiment. The observed native row event vs serializer lookup mismatch is explicitly an inference.
- **Live localization preview and persistence/undo:** source-only T05; T13 validates file subprocess operations, not live translation resources or visual preview. No culture-switch durability/preview timing test.
- **5.5 / 5.6:** stale registry paths, no source directory. 4.27/5.3 observation declarations were inspected, but no sync probe build/runtime there. 4.27 process lane lacks an import recipe, so its import was not run.
- **Exact existing authoring gate on 5.8:** script explicitly pins 5.7 and fails before tests. Research probe runtime on 5.8 does not substitute for that unavailable gate. First 5.7 baseline attempt failed missing built protocol exports; package build prerequisite and Node 26 rerun passed.
- **Isolated performance causes:** synchronous probe logging adds overhead; full-response serialization, transfer and cache evictions affect timings/RSS. No peak backup allocation profile, fingerprint stage split, WAN/end-to-end UI test, history saturation or long-session steady-state run.
- **Process ownership retrospective completeness:** the first baseline watcher used PID-only ancestry, susceptible to reuse. Its candidate lists are journaled; final independent Win32 inventory found no remaining engine/service processes. Future helper now checks creation times; that inspection was smoke-tested without rerunning baseline gates.

## Recommended first spike based on evidence

**Opinion: attempt a bounded DataTable authority/observer spike before committing to a generic product sync layer.** Keep it library/CLI-usable and separately enable the editor capability, preserving UE Shed's headless-first boundary. Direct native hooks and domain notifications have stronger evidence here than adopting Concert wholesale.

The spike should attach to one small scalar table and the five-table batch, tag request provenance, publish one confirmed operation/revision after engine finalization, preserve Undo/Redo as new authority operations, mirror dirty/save state, and reattach after reload. Use correct DataTable pre/post notifications and a row-aware cache/diff; handle cancellation and raw-script notification contracts explicitly. Keep optimistic overlay settlement waiting on correlated authoritative state, not merely a successful transport return. Fence an already-active editor transaction so the idle-editor undo result is not overgeneralized.

Acceptance evidence must include both 5.7 and 5.8, actual open row widgets and structural edits, one five-table undo/redo, stale-write rejection, request-echo attribution under undo and reentrancy, push recovery, and **normal** unfocused/minimized editors. Profile the 10,000-row path before deciding between native deltas, cheaper confirmations or bounded full-table refresh. Repeat the ≤100 ms one-cell p95 target under that policy. Evaluate localization live preview as a separate capability spike with explicit persistence and culture/resource boundaries.
