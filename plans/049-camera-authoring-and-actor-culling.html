01

From a demo to an authoring workflow

The core already knows how to generate arbitrary arc and ring counts, store approved views, and hide explicitly named actors. The missing work is making those capabilities coherent, responsive, and safe to revise.

Current friction

Useful primitives, awkward composition

The default six candidates combine three presets. Framing regeneration clears the selected manual draft pose. Hidden actors are entered as text paths, and the remote image loop makes fine camera adjustments cumbersome.

Proposed experience

One draft across two surfaces

UE Shed organizes views and portable intent. Unreal supplies direct manipulation and actor selection. Both edit the same revisioned draft through public services.

Product scope. Actor-oriented views belong to Map Review. Orthographic Map Capture reuses the visibility primitives at whole-plan scope; its tile geometry stays deterministic.

The author’s path

  1. Choose a subject and a starting layout

    Adjust FOV, distance, height, aim, and distribution within the active camera set linked to the selected subject actor. Choose the whole set, a group within it, or selected cameras within it.   4. Select what this view should hide

Shared tuning belongs to one actor’s active camera set. A Review Set can store views for many actors. These controls affect only the chosen arrangement linked to the current subject. If that actor has several arrangements, choose one explicitly. Reusing a recipe does not link their edits.

A manual pose does not detach the lens

Moving a camera in Unreal pins its pose. FOV keeps inheriting unless that field is overridden. Shared framing changes show which manual poses will be skipped. Including them is a deliberate batch transformation.

Regeneration is a reviewed change

Changing count or layout produces a retained/added/moved/removed diff. A customized camera keeps its identity and can survive as a manual view. Its exceptions never migrate to a different camera by array index.

Parameter meanings and fitting behavior

FOV is horizontal degrees with output aspect shown. Fitted cameras recompute fit distance when FOV changes; manual cameras change the lens at their saved location. Margin must be validated on both image axes.

Distance multiplier is relative to generated fit; manual Dolly is a separate explicit movement. Normalized elevation and world-Z offset in cm are distinct. Aim offset declares world or subject coordinates. Follow-target views retain their existing relative-pose semantics and reconcile target drift.

The present Review schema is perspective and fixed to 16:9. Aspect-aware fitting requires schema and conformance work. CineCamera filmback, focus, and Sequencer support are outside this proposal.

04

Visibility the author can explain

An actor list is part of a view’s intent. Give each entry a destination, a reason it applies, and a resolution state. Heuristics can suggest blockers; the author chooses the exclusions.

Selection with a pinned destination

Keep “View E” active while selecting the column in the Outliner. Import the selection snapshot into View E’s hidden list. Reveal excluded actors temporarily for picking without changing saved rules.

Destination: View EHide selected actors

Readable actor entries

Show label, stable locator, inherited or local origin, and resolved/missing/ambiguous state. Reveal in Outliner, remove a local rule, or override an inherited exclusion from the same list.

Column · Local · Resolved
  1. Start with the exact immutable preset’s exclusions.
  2. Apply local removal and addition of exclusions by actor identity.
  3. Protection wins over exclusions; report suppressed rules.
  4. Protect the Review subject by default and reject self-exclusion.
  5. Resolve actors to supported renderable components and deduplicate aliases before rendering.

Protection prevents UE Shed from hiding an actor. It does not load or reveal geometry that the world already hides. GUID identity is map-scoped; names and last-known paths are diagnostic. Missing actors never resolve to a similarly named replacement.

Output choice Meaning Failure behavior
Original No authored visibility intervention. Preserve the existing Pure/Natural meaning. Normal capture and subject-resolution failures remain explicit.
Authored Apply saved visibility rules. Permanently label the image and record actual intervention. Missing exclusions block by default; explicit skip-missing policy records each skip.
Original + Authored Same approved camera, with both outputs and their policy evidence. Keep a valid Original image if Authored fails; return a typed partial result.
Renderer work is still required. SceneCapture has component-local hiding. The current editor viewport renderer reports Clear unsupported. A prototype must prove per-view exclusion in the viewport and screenshot pipeline before advertising support. Global actor hide flags are not an acceptable substitute.
Visibility evidence, limits, and tile capture

Record requested locators, resolution outcomes, affected actors/components, policy revision, renderer, protected/skipped entries, and restoration. Authored-only output is a versioned contract extension; legacy Pure/Clear artifacts remain readable.

Negotiate bounded actor/component limits. The existing 32-entry lists cannot be silently expanded or truncated. Child actors, instanced levels, HLOD replacement, partition loading, and newly registered components need honest support and resolution results.

For tiles, one immutable visibility definition applies across zooms, batches, warmup, and metering. Save it with the plan snapshot and manifest. Individual tile-camera edits remain outside the geometry contract.

05

A native companion, a shared domain

Add an optional editor-only UEShedCameraAuthoring plugin depending on a separately opt-in UEShedCameraAuthoringBridge. The bridge owns proxies, piloting, editor events, and synchronization with the Node host. It depends on UEShedCameras for rendering and visibility. Existing capture consumers need neither authoring plugin.

Our menu is optional. The authoring contract is public. A studio can install UEShedCameraAuthoring or build its own Unreal menu against the same camera package and public native bridge. A custom menu must work with our menu plugin disabled and Workbench absent.

Local movement stays local

Camera flight and dragging never wait for a host acknowledgement or pixel stream. Coalesce small pose updates at a bounded starting rate of 5–10 Hz, and reliably flush the final gesture. Measure latency separately from polling rate.

One framing implementation

Shared parameter changes use the public TypeScript domain service; the panel shows pending state until the generated result arrives. A CLI-attached host can serve the panel. Unreal does not need Electron or a copy of the generator.

Studio integration and replaceable menus

The package owns actor-scoped commands, framing, canonical drafts, revisions, persistence, approval, and recovery. Public transport and storage ports allow a studio host to supply its own adapters.

A C++ menu exchanges versioned commands, events, and snapshots with an external host running the TypeScript package. It can reuse the public CameraAuthoringBridge without installing our menu plugin, or provide its own adapter implementing the same contract. Expanded panels and hover state stay local; commands describe domain intent.

Ship an adoption guide, command/state schemas, native custom-menu example, dependency manifest, and conformance runner. Our menu must use exactly the same public APIs, with no private endpoints or plugin-name checks required for custom clients.

A future sync layer can fit here

Reserve the interface now; keep a general sync engine out of scope. Menus observe local state and submit domain commands through a public authoring client. A replaceable adapter handles pending edits, acknowledgements, change delivery, and reconciliation. This feature implements only the small adapter needed for the existing transport.

TanStack DB provides useful precedent: synced collections, a separate optimistic overlay, and reactive queries over local state. The intended direction is a UE Shed-specific synchronization library inspired by that separation. No TanStack DB dependency or full database implementation is proposed. TypeScript and native facades share a neutral protocol; domain authority stays in the camera package.

Start with scoped subscriptions, pending commands, confirmed changes, and recovery. General queries, joins, indexing, incremental query execution, and offline multi-writer merging are separate infrastructure projects. Extract a broader library after a second real UE Shed workflow validates the boundary; evaluate third-party internals separately.

  • Open: actor/arrangement-scoped snapshot plus a matching cursor and producer epoch, so subscribing cannot miss intervening edits.
  • Changes: ordered atomic batches with stable entity IDs, upserts, deletions, commit identity, and causing operation IDs.
  • Submit and recover: explicit commands, expected revisions, idempotency, and pending/rejected/durably committed outcomes.
  • Observe and close: reactive confirmed/pending state, honest conflict status, and scoped resource cleanup.

Responses and change-feed echoes share operation/commit identities. Remove an optimistic overlay only when matching committed state is installed. Cursor gaps require reset and reconciliation. An acknowledged draft is still separate from an approved Review Set.

Keep live gesture samples, pilot ownership, and image frames outside document replication. A store adapter translates edits into domain commands; it cannot bypass framing or actor scope by writing raw camera rows. Regeneration publishes all affected cameras as one atomic change.

Vendor types never appear in the public protocol. Polling can later be replaced by push delivery behind the same port. A shared sync platform, offline multi-writer merging, and a TanStack DB dependency remain deferred.

Synchronization and concurrency contract

Proposed capability: editor.camera-authoring.v1. Open, inspect, patch, select, pilot, read changes since cursor, acknowledge, renew lease, and close all carry explicit identities and revisions.

Native actions emit bounded commands/events to the host. Pose samples coalesce; completed gestures, culling commands, and Undo/Redo boundaries remain reliable and ordered. Gaps require snapshot reconciliation. No new image transport or callback server is needed.

Mutation IDs make retries idempotent within a declared retention window. Per-camera edit ownership prevents concurrent external batch edits during a gesture. Stale revisions surface conflicts; host snapshots must not echo back as new edits.

Viewport and camera lifetime

Use transient editor-only CameraActor-derived proxies with stable session/camera correlation. Materialize the working set on demand. Verify Outliner visibility, duplication, deletion, save/autosave, PIE, and Undo/Redo without changing map or external actor dirty state.

Piloting borrows one explicit viewport and snapshots its owned state. Refuse foreign/cinematic locks. Restore only state still owned by the session. Flush edits and release pilot/visibility ownership before capture; background previews cannot steal the viewport.

Map changes, PIE, viewport destruction, module shutdown, and lease expiry release resources and expose resumable or stale state. The new plugin must use a public ownership API, not the existing renderer’s private header.

06

Keep the intent after the session ends

Durable draft

Link each arrangement to one explicit subject actor and validate camera membership on every batch command. Reject requests spanning actors or arrangements. Switching actors cannot retarget pending edits. Extend the existing authoring session with stable camera IDs, per-camera poses, field overrides, visibility rules, recipe provenance, revisions, and a base Review Set digest. Generation slots and display order are not identity.

Approved snapshot

Save freezes effective poses, lenses, policies, and authoring provenance. Revision affected Views when pose or visibility changes. Capture reads the saved snapshot; reopening for editing can recover the recipe and exceptions.

Condition Required behavior
Two writers Validate the base digest under a cross-process lock. Atomic rename alone cannot prevent lost updates.
Crash during approval A recoverable commit record prevents duplicate appended Views after set save but before session status update.
Disconnect mid-gesture Show pending edits and retain a bounded buffer while the lease is valid. Expose a recovery patch before expiry.
Editor crash Acknowledged drafts survive in the host. An unacknowledged gesture may be lost and must never have appeared saved.
Reconnect or world change Reconcile snapshots and revisions. Never replay against another map or a regenerated camera.
Undo / Redo Produce fresh draft revisions. Prove native transactions preserve unrelated editor history and do not resurrect dead proxies.
Headless capture stays independent. The Core+Cameras bundle must capture the saved definition without CameraAuthoring enabled. The native panel is an optional authoring surface.

Implementation surfaces

packages/cameras owns schemas, framing, sessions, persistence, visibility, render translation, and tile adoption. Language-neutral wire contracts and fixtures live in the existing contract surfaces.

unreal/Plugins/UEShedCameraAuthoring adds the native panel, menu actions, Details customizations, and client wiring. UEShedCameraAuthoringBridge owns proxies, editor lifecycle, and native synchronization. UEShedCameras exposes engine ownership primitives and scoped rendering without an authoring dependency.

extensions/camera-review supplies the maintained workflow. CLI and Workbench compose public services. Plugin bundle and fixture tooling add an optional authoring dependency closure and exact-engine artifacts.

Unreal source evidence and stop conditions

UE 5.7 source exposes actor locks in LevelEditorViewport.h, movement completion in Actor.h, actor-moved events in Engine.h, property/transaction delegates in UObjectGlobals.h, temporary actor spawn options in World.h, and per-view primitives/hooks in SceneView.h and SceneViewExtension.h.

Stop promotion if proxies dirty maps, undo recovery fails, or capture and pilot ownership compete. Stop advertising viewport culling if the correct view and screenshot pipeline cannot be demonstrated. Return unsupported capability rather than hiding globally or switching renderers silently.

08

The production bar

Prove the exact authoring scenario.

Keep another actor’s camera set and a second arrangement for the same actor in the Review Set throughout this journey. Their definitions and View revisions must remain unchanged by tuning the active set. Also reject mixed-membership batch requests and verify pending edits retain their original actor/set when the author switches context.

  1. Create six orbit views. Set 1.25× distance, 40° FOV, and +100 cm height. Give one camera 55° and manually move another.
  2. Pilot cameras in Unreal. Hide a column in one view, add shared exclusions, and protect an actor in another view.
  3. Change shared framing again. Generated poses move; the manual pose stays; FOV inheritance and per-view visibility remain correct.
  4. Change the camera count. Review the diff and retain a customized camera without reassigning its identity.
  5. Save, close both applications, reopen, revise again, and capture through the CLI with only Core+Cameras enabled. Verify saved poses, exclusions, labels, pixels, and unchanged package dirty state.

Behavior and recovery

Also cover one current-view camera, 37 cameras with previews disabled, simultaneous clients, stale acknowledgements, retry after lost response, disconnects, proxy deletion/undo, missing blockers, map switches, PIE, and cancellation.

Truthful validation

Use pure and contract tests for semantics, native automation for pixels and restoration, and recorded E2E for the full journey. Measure interaction overhead, acknowledgement latency, preview age, memory, and queue bounds.

Menu replacement is a release gate. Build a separate minimal Unreal menu against public headers and a clean camera-package consumer. With Workbench absent and UEShedCameraAuthoring disabled, prove create → edit from both clients → cull → sync → save → reopen → capture, including the same actor scope, conflicts, and recovery behavior.

Native evidence must delimit support for static meshes, Nanite, instanced geometry, translucency, and partition/loading cases. No responsiveness claim follows merely from a polling rate, and no viewport culling claim follows merely from finding a hook in the engine source.
