## Context

On a review page every Blueprint in a changelist shows "Binary file — text diff not available".
Game Text now shows what a change does to text (Plan 060); this plan does the same for a
Blueprint's logic: which nodes came and went, which defaults changed, which wires moved.

A text form of the graph diffed line by line would mislead. Two things in a saved Blueprint change
all the time without the logic changing: node positions move whenever someone tidies a graph, and
a recompile renumbers generated object names (`K2Node_CallFunction_12` becomes `_13`). Plan 060
saw the second in game text, where cutscene lines showed as removed and added after a recompile.

## Decisions

1. **Compare the projection, natively.** The diff runs in `uasset-inspection` on two
   `BlueprintGraphProjection`s, so the engine and the WebAssembly reader share it. Only the diff
   crosses into TypeScript, never either graph.
2. **Identity, not names or places.**
    - Graphs pair by `GraphGuid`, then object path, then name; a graph whose name changed is
      renamed, not removed and added.
    - Nodes pair by a `NodeGuid` that is unique on both sides, else by object path.
    - Pins pair by id, then by direction and name, so a reconstructed node's new pin ids keep their
      wires.
    - Wires compare through those pairings.
3. **What is not a change.**
    - Position, size and renumbering are counted (`nodes_moved`, `nodes_renumbered`) and never
      listed.
    - Editor and compiler state on a node is ignored: compiler messages, comment bubbles, advanced
      pin display, upgrade notes.
    - A pin's hidden flag, tooltip and autogenerated default are ignored.
    - A linked input's default is ignored: the wire supplies the value.
4. **What is a change, and how it reads.**
    - A node added or removed carries its wires to nodes on both sides ("Delay: `execute` ←
      OpenDoor.`then`"). Its own wires are not listed again.
    - A node changed lists pins added or removed (a function's new parameter), pin types, pin
      defaults (3 → 5) and other properties (a function's target, a comment's text). A changed
      title or class shows the before label.
    - A wire between kept nodes is added, removed or **rewired**: a wire whose one end stayed while
      the other moved, when that end lost one wire and gained one.
    - Variables pair by GUID, then name: added, removed, renamed, and type, default, category or
      flags changed. A changed parent class shows.
5. **Unread is not removed.** A node one side lists but could not read is counted as unread and
   left out, with its wires. The reader's gaps (Phase 1) must not read as deletions.
6. **Values are cut at 160 characters.** A struct default or a property can be long; the diff
   shows enough to recognise it.

## Phases

### Phase 1: Reader coverage

The 2026-10-17 stress run rejected 1,627 of 4,546 Blueprint candidates, and large assets read in
part. A diff is only as good as what it reads.

- Measure on real changes: how many Blueprints in a project's recent changelists read in full, in
  part, or not at all, and why (by failure code and gap reason).
- Fix the commonest causes in the parser, largest first, with fixtures.
- **STOP** if a fix needs a class-name allowlist or a new loaded-Unreal dependency.

### Phase 2: The native graph diff

- `uasset_inspection::blueprint_diff::diff_blueprints(before, after)`, typed, tested on built
  graphs (moves, renumbering, a default, an inserted node, a rewire, a reconstructed node, a new
  parameter, an unread node, graphs and variables).
- Check it against real changelists the way Plan 060 was, before anything is shown: every listed
  change in a sample of pairs is read against the editor or a commandlet.
- An engine request, `compare_blueprints`, taking two paths (either may be absent for an added or
  deleted asset) and returning counts and one page of changes, with spans and stage times
  (`read`, `project`, `diff`).
- **STOP** if a sample shows a change the editor does not, or misses one it does, that the
  identity rules above cannot explain.

### Phase 3: A text summary on the review page

- The diff through `TextDiff` beside the text report: a section per graph, entries per node and
  wire, the counts as the overview ("12 nodes moved, 3 renumbered").
- Two design-review rounds and two code-review rounds, like Plan 061.

### Phase 4: The highlighted diagram

The research's port graph lays out the union of before and after once and colours what was added,
removed and changed, so the diagram does not shift under the reader (adding one node moved 29 of
275 others in separate layouts). This needs a scoped Pele fork with a public model and scene API,
and the open items from the research: wires crossing nodes, denser cyclic graphs, nested groups,
pin hierarchy and comment ownership, and a bounded, cancellable layout worker.

## Not in this plan

- Control Rig Blueprints (the RigVM model is a separate serialization surface).
- Merging, or three-way diffs.
- Animation Blueprint state machines beyond their graphs' nodes and wires.

## Evidence

### Phase 2 started (2026-10-30, overnight, before owner review)

**Corpus.** A large UE 4.27 project's 80 latest content changelists, read-only (`p4 changes`,
`p4 describe -s`, `p4 print`): 121 Blueprint and Widget Blueprint edits across 23 changelists,
each at its revision and the one before, 136 MB in all. The harness is
`crates/uasset-io/src/direct_executor/blueprint_diff_corpus.rs` (ignored by default; it names its
two environment variables).

**Reads and diffs.** Every pair read on both sides and diffed; none failed. Release build, one
thread:

| Step            | Median  | 95th percentile | Largest |
| --------------- | ------- | --------------- | ------- |
| Read both sides | 12.5 ms | 70 ms           | 196 ms  |
| Diff            | 1.4 ms  | 10 ms           | 28 ms   |
| Diff as JSON    | 10 KB   | —               | 237 KB  |

The largest pair is a HUD widget of about 1,550 nodes, 4.4 MB a side: 99 ms to read one side,
28 ms to diff. Phase 2's engine request needs no cache to be quick, but it should page: the
largest diff is a quarter of a megabyte.

**What the diff found**, summed over the 121 pairs:

- Graphs: 138 added, 124 changed, 578 unchanged, none removed.
- Nodes: 3,181 added (most in the added graphs), 293 removed, 135 changed, 17,142 unchanged.
  932 moved and 769 renumbered, which a line diff would have shown as changes. None unread.
- Node edits: 77 pins added, 37 removed, 30 retyped, 67 defaults, 67 properties.
- Wires between kept nodes: 14 added, 84 removed, 7 rewired. A node inserted into a chain
  removes one wire and carries its two new ones, which is why removed outnumbers added.
- Variables: 103 changed.

**Noise found and taken out**, from reading the diffs against what the changelists say:

- 285 of 352 default changes were a literal replaced by a wire from a new node (a Select's
  option now fed by a new "is docked" check). The new wire is on the added node, so a default
  under a pin that is now wired is not listed; an input that lost its wire shows the default that
  now applies, if it has one.
- Struct and array properties showed as one JSON value cut before the part that differed. They
  now compare by leaf, named by path (`FunctionReference.MemberParent`), at most six per property.
- Pin visibility bookkeeping (`ShowPinForProperties`, `NumOptionPins`, `NumAdditionalInputs`)
  repeated pins the diff lists as added and removed; a member reference's `MemberGuid` changed
  without its name or parent changing.

**Not compared yet, and it shows.** 22 pairs had no graph or variable change: widget layouts,
components and class defaults, which this diff does not read. The summary must say what it did
not compare rather than "no change". This is Phase 2 work, below.

**Not yet checked against the editor.** The listed changes were read against the changelists'
descriptions, not opened in Unreal. Phase 2's STOP check (a sample read against the editor or a
commandlet) is still to do.

**Next in Phase 2:**
