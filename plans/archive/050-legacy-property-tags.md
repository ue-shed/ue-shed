## Outcome

Game Text extraction works on classic, uncooked, versioned editor packages saved by UE 4.27 and by
UE 5.0–5.3. This covers String Tables, DataTable cells, data assets, and generic UObject text
properties. The change is a legacy `FPropertyTag` reader that feeds the existing type tree and
codecs. Generic inspection and levels gain the same version window as a side effect. Features that
decode native binary layouts stay pinned to their verified versions. On older packages they return
`UnsupportedVersion` or an explicit coverage gap. This plan resolves the roadmap's deferred "engine
compatibility window" decision for tagged properties only.

## Fixed decisions

- **Scope is tagged-property text.** In scope: String Tables, DataTable and CompositeDataTable rows,
  data assets, and generic UObject text (including CDO defaults and widget subobjects).
  Blueprint graph pins, Sequencer native channels, AnimSequence, Skeleton, property bags,
  InstancedStruct, and actor/component native records stay pinned to their current versions.
  On legacy packages they report gaps; they do not get new decoders.
- **Version window.** The legacy reader handles `FileVersionUE4 == 522` with `FileVersionUE5`
  absent (UE 4.27), or `FileVersionUE5` in `1000..=1011`. From 1012 the existing reader applies. Packages saved with `FileVersionUE4 < 522`
  (UE 4.26 and older) stay `UnsupportedVersion`, with recovery guidance to resave in 4.27 or later.
  Widening this needs fixture evidence from those engines and is a separate decision.
- **One type tree.** Legacy tags become the existing `PropertyTypeName` tree, so codecs dispatch the
  same way for both readers. Do not fork the codecs per reader. Version-specific payload differences
  live in the codec as explicit version gates.
- **Missing type information is a gap, not a guess.** Legacy map keys/values and set elements do not
  record their struct type. Try to decode them as self-delimiting tagged streams, bounded by the
  container tag size. If that fails, retain the bytes as `Raw` with a new specific reason and report
  a text coverage gap. Never infer a native struct width from heuristics.
- **Bounded failure.** Every legacy record is consumed by its tag `Size`. A codec failure inside a
  record never moves the stream past the record boundary.
- **Fixtures are generated by real engines.** Each engine saves the legacy fixtures and reloads them
  in a fresh process for API evidence, matching the existing matrix practice. Engine content is
  never checked in. Synthetic byte tests cover the version gates that have no installed engine.
- **The verification matrix gains 4.27 and 5.3** for this surface. The existing UE 5.7 + 5.8
  requirement is unchanged.

## Source facts verified on 2026-10-07

Read from `EpicGames/UnrealEngine` at tags 4.27, 5.0, and 5.3. Local 5.7/5.8 source still contains
the backward-compatible loader. Re-verify each fact before relying on it.

- **Tag layout is identical across 4.27, 5.0, and 5.3:**
    - Fields: `Name`, `Type` (FName), `Size` (i32), `ArrayIndex` (i32).
    - Type-specific extras: `StructName` + `StructGuid` for `StructProperty`; a `BoolVal` byte for
      `BoolProperty`; `EnumName` for `ByteProperty` and `EnumProperty`; `InnerType` for
      `ArrayProperty` and `SetProperty`; `InnerType` + `ValueType` for `MapProperty`.
    - Then a `HasPropertyGuid` byte and an optional `PropertyGuid`.
    - The only difference is that 5.3 also writes `InnerType` for `OptionalProperty`.
    - Extras are written only when the type FName number is 0.
- **Version boundaries:**
    - UE 4.27 saves UE4 522 (`VER_UE4_CORRECT_LICENSEE_FLAG`) with no UE5 version.
    - The newest UE5 version in UE 5.0's enum is 1004 (`LARGE_WORLD_COORDINATES`).
    - The newest in UE 5.3's enum is 1009 (`DATA_RESOURCES`).
    - 1010–1012 arrive with 5.4; complete type names start at 1012.
- **`ETextHistoryType` indices are unchanged since 4.27.** None = -1, Base = 0, StringTableEntry =
  11, TextGenerator = 12. The text wire format is the same: flags, history type, and per-history
  payload. For `None`, the culture-invariant flag is gated by `FEditorObjectVersion`
  `CultureInvariantTextSerializationKeyStability`.
- **`FStringTable` wire format is unchanged from 4.27 to 5.3:** namespace string, entry count,
  key/source string pairs, then the key-to-metadata map. Only in-memory key types changed.
- **`UDataTable` row loading is unchanged:** row count, then for each row an FName followed by the
  row struct's tagged stream.
- **UE 4.27 saves a folder name in the summary's name string; UE 5.3 saves the package name.**
  Verified in each engine's `PackageFileSummary.h`, `PackageFileSummary.cpp`, and `LinkerSave.cpp`.
  Evidence records both the loaded API object path and `serialized_package_name`. Byte-only parser
  object paths use that serialized prefix (normally `None` on 4.27); fixture comparisons retain the
  distinction and compare text property paths within each independently identified asset. The
  fixture must not set an artificial package folder merely to make it look like a UE5 package.
- **5.0+ math structs (`LARGE_WORLD_COORDINATES`, UE5 1004) use double components.** Older packages
  use floats. This matters wherever there is no per-element size, for example arrays of native
  structs.
- **`FSOFTOBJECTPATH_REMOVE_ASSET_PATH_FNAMES` (1007) changes the inline soft-path layout.**
  `ADD_SOFTOBJECTPATH_LIST` (1008) adds the package soft-path table.

## Phase 1: Legacy tag reader

1. Lift the `UE5_PROPERTY_TAG_COMPLETE_TYPE_NAME` rejection in `read_tagged_property_stream` and
   dispatch on version to a legacy reader inside the window. Packages outside the window keep
   `UnsupportedVersion`.
2. Read the legacy tag and convert its type information into `PropertyTypeName`. Containers carry
   inner/value types. Struct tags carry the struct name and GUID. A struct name that cannot be
   resolved stays an unresolved struct, not an error.
3. Handle `BoolVal` (payload size 0), byte properties with and without an enum, enum properties, and
   `HasPropertyGuid`.
4. Handle `1011` property extensions and class serialization-control extensions for the 1011 range,
   following the 5.7 loader.
5. Add synthetic tag-level tests for each type extra, each version gate, and the terminator.

## Phase 2: Version-gated payloads

1. Gate math-struct widths on `LARGE_WORLD_COORDINATES`. Cover every native struct the codecs decode
   (Vector, Vector2D, Vector4, Rotator, Quat, Plane, Box, Transform members), whether reached
   through a tag or an array inner tag.
2. Gate soft object path decoding on 1007 and 1008, following each version's `SoftObjectPath.cpp`.
3. Decode legacy map and set struct elements under the "missing type information" decision, and add
   the specific `Raw` reason.
4. Confirm the text dev-notes gate and the culture-invariant gate in `decode_text_value` produce the
   right layout for 4.27 and 5.3 custom versions.
5. Add synthetic payload tests for each gate at, below, and above its boundary.

## Phase 3: Inspection, IO, and WASM

2. Make sure text coverage gaps distinguish "unsupported history" from "legacy container element

- A wire fact above disagrees with the engine source for its version. Update this plan first.

- Fixture generation needs checked-in engine content, or a fixture C++ change that would also touch
  the UE 5.7 fixture project.
