## Source and current-coverage findings

Declarations and serializer framing were checked in local UE 5.7.4 and 5.8.2 source.
The findings below record the starting gaps; all five targets are now implemented and verified.

- `Runtime/MovieScene/Public/MovieSceneSection.h` stores the shared section fields as reflected
  properties. The current projection exposes a range and channels but omits these settings.
- `Runtime/MovieScene/Public/MovieScene.h` stores `CameraCutTrack` separately from `Tracks`.
  The current projection traverses `Tracks` only. `MovieSceneCameraCutSection.h` stores
  `CameraBindingID` and `bLockPreviousCamera`; camera binding evidence must retain scope rather
  than guess a runtime actor. Current binding metadata only joins possessables.
- `Runtime/MovieSceneTracks/Public/Channels/MovieSceneStringChannel.h` stores reflected frame/string
  arrays and default fields. `Runtime/MovieScene/Public/Channels/MovieSceneObjectPathChannel.h`
  stores frame/key arrays, a property class and a default key. Its key struct retains both soft
  and hard references. Existing generic codecs and reference inventory provide most of the base.
- `Runtime/Engine/Classes/Engine/Blueprint.h` stores `NewVariables` as `FBPVariableDescription`
  records. These include GUID, `FEdGraphPinType`, category, flags, replication settings, metadata
  and optional default text. `FEdGraphPinType` enables a native serializer on both engines;
  extend the existing pin-type decoder into a shared, source-checked property recipe as required.
- `SimpleConstructionScript.h` and `SCS_Node.h` store root/all nodes, child links, component classes,
  template references and parent component identity. Existing Blueprint output projects graphs
  only; generic decoded exports already provide the starting point for component evidence.
