# Game Text scale harness

Plan 057 Phase 1 tools run from the repository root. They are internal scripts, never package
exports. Build the packages first after a fresh checkout or product-source edits:

```powershell
pnpm run build:typescript-packages
pnpm generate:game-text-scale --scale 1x --seed 57 --root test-results/game-text-scale/project-1x
pnpm benchmark:game-text-scale --project test-results/game-text-scale/project-1x --heaps default,16384 --output test-results/game-text-scale/baseline-1x.json
pnpm validate:game-text-scale --project test-results/game-text-scale/project-10x-final --output test-results/game-text-scale/validation-10x.json
```

`--scale 0.01` also works. The generator refuses an existing root. Inputs and outputs must stay
inside this checkout. Every generated byte is independent of the output root, including the
relative paths in `saved-text.ndjson`. The replay adapter relocates those paths. `scale.json`
records the recipe and seed; generation timings, logical file bytes and recipe hash are written
beside the project. No `.uasset` files are generated. File writes buffer at most 512 Ki characters;
only package occurrence counters grow with the package count. Tiny recipes have minimum counts
so all evidence kinds can be exercised.

The retained `project-10x-final` is later phases' input. Do not regenerate it or run today's
in-memory pipeline on it. The benchmark refuses recipes at scale 10 or above. The validator streams
each file in 1 MiB chunks, checks recipe-specific entry/event token counts, BOMs, framing and
expected file presence, and reports logical file bytes by kind and per file. This is a cheap
completeness census, not full JSON/PO syntax or semantic validation. Tiny tests prove syntax with
the existing parsers. The validator also accepts the pre-crash 1× descriptor's legacy recipe name.

The generator extends Plan 056's shared data helper and PO serializer. It writes a Dashboard
target and gather recipe with `%LOCPROJECTROOT%` filters, UTF-16LE BOM manifest/archives, UTF-8 BOM
and CRLF PO files, raw U+2028 in PO text, invented sources and translations, saved package namespace
markers, keyless occurrences, editor-looking properties, duplicate sources, DataTable cells,
String Table definitions and references, missing saved keys, C++/ini gathered paths and key changes.
The four gap reasons repeat in fixed proportions. Most namespaces are empty, with one large
namespace, table namespaces and small namespaces. The ten-culture recipe becomes twenty at 10×.

Each heap setting runs the entire current pipeline in a fresh child, with `--expose-gc`, isolated
from inherited `NODE_OPTIONS`. `--heaps` takes `default` or comma-separated MiB limits. Stages are
evidence (including target discovery), corpus (schema-validated event replay through the real
`TextCorpusService` and an `AssetReader` test layer), join (including persisted review and key
changes), and status (query construction, one 50-line search page and `localizationStatusReport`).
Inputs remain retained across stages, just as in today's CLI.

Memory samples run every 25 ms, with IPC updates every 250 ms and explicit checkpoints. Synchronous
parsers and joins block that timer, so V8's pre-GC trace sizes also contribute heap peaks; array
buffer peaks remain sampled lower bounds. A parent polls OS RSS every second and enforces the
default 20 GB RSS (20,000,000,000 bytes) and 1,200-second per-stage limits independently of the
child's event loop. On Windows it refreshes `Get-Process.WorkingSet64` and terminates the process
tree with `taskkill /T /F`; on POSIX it kills the worker's process group. Invalid/failed OS samples
stop an active run instead of silently disabling protection. `--heaps` cannot exceed 16,384 MiB;
`--max-rss-gib` and `--stage-timeout-seconds` may only lower their hard caps. OS probes time out
after three seconds. Polling can overshoot a limit between samples. Stage durations include their
final GC; total duration includes process startup
and cleanup. Results include final retained memory, counts, completed stages and the failed or
stopped stage with its error. Any failed/stopped run makes the command exit nonzero. Evidence
file failures are failures even when the evidence service returns them as typed values. The
benchmark keeps production evidence limits. The preserved pre-crash `baseline-10x.json` failed
in evidence with `limit_exceeded` in 0.090 seconds: all 10× localization files exceed 320 MiB,
and their 1,326,060 entries also exceed the per-file entry cap. No override or retry is safe with
today's object model. The Phase 1 plan records this historical failure separately from the 10×
pipeline's current **not run** status. Existing 1× results stand; none exceeded the new hard caps.

`localization-join-oracle.test-support.ts` is Phase 5's semantic comparator. It compares all join
fields by stable line ID, reports a bounded readable list and uncapped counts, and documents
which arrays are sets, multisets or ordered values. It accepts already decoded `LocalizationJoin`
values; importing another implementation is the caller's boundary responsibility.

CI only uses scale 0.001 (133 keys, 1,028 occurrences, 4,800 gaps):

```powershell
pnpm exec vitest run scripts/game-text-scale.test.ts packages/localization packages/game-text
```

The localization import benchmark enforces an absolute 900-second limit for every 10× run,
including startup, discovery, all cold files and cleanup. File/stage changes do not reset it.
Expired runs kill the worker tree, exit nonzero and record `outcome.kind: "failed"`, with any
completed stages retained for diagnosis. `--run-timeout-seconds` can only lower the applicable
limit. A parent-owned byte guard restores the PO edit even after forced termination.

The dictionary experiment reads retained Phase 2 sections without importing projects or rebuilding
the join. Run each candidate separately and serially; the same heap/RSS/stage and 10× run caps apply:

```powershell
node --import tsx scripts/benchmark-game-text-dictionary.ts --input test-results/game-text-scale/snapshot-v3-final-1x-256.snapshot --output test-results/game-text-scale/dictionary-A64-1x.json --scale 1 --candidate A64
node --import tsx scripts/benchmark-game-text-dictionary.ts --input test-results/game-text-scale/snapshot-v3-final-10x-256.snapshot --output test-results/game-text-scale/dictionary-A64-10x.json --scale 10 --candidate A64
```

Candidates are `A16`, `A32`, `A64`, `B` (BBHash gamma 1, sampled rank, fingerprint and insertion-ID
mapping) and `C` (current hash pages). The script verifies declared scale against the saved line
count. Results separate input loading, dictionary encoding, a modeled file append, scattered-page
decode and prefix ranges. Lookup/page probes start with compressed payloads in memory; they are
not end-to-end importer or production reader measurements. Method, comparisons and remaining work
are in [the measurements](../docs/engineering/game-text-shared-index-measurements.md).
